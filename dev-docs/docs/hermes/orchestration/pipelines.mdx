A **pipeline** is a named workflow scoped to one [domain integration](/hermes/integration/integrate-domain-with-hermes). It runs a sequence of **steps**; each step targets a registered agent version and carries JSON **input** and **config** shaped by that agent’s schemas.

## What defines a pipeline

- **Domain integration**: Every pipeline belongs to exactly one integration. Step agents must be registered for that same integration.
- **Steps**: Ordered by `order`. Each step references `agentId`, `agentVersion`, optional saved **agent config**, and JSON `input` / `config` (see [step input syntax](/hermes/packages/hermes-step-input-syntax)).
- **Active**: When `isActive` is off, the pipeline is treated as disabled for scheduling and similar flows (see [pipeline status](#pipeline-status) below).
- **Description & metadata**: Optional fields for operators; execution-specific options can use `executionConfig` where the product supports it.

## Editing and running

The dashboard provides:

- A **Pipelines** list with create/edit and row actions.
- A **pipeline detail** view to add, reorder, and edit steps, pick agents from the registry, and fill inputs using the JSON schema form when available.
- **Run pipeline** for a manual execution, plus **Executions** and per-execution detail (steps, status, errors).

## Pipeline status

The UI derives a **status** from validation and `isActive`:

- **Incomplete**: Validation failed (for example missing agent in registry, schema errors, or invalid data source expressions in step input). Those pipelines are not safe to schedule or run until warnings are addressed.
- **Disabled**: Valid but `isActive` is false.
- **Enabled**: Valid and active.

Empty pipelines (no steps) validate as complete; add steps before relying on them in production.

## How schedules and HTTP triggers use pipelines

[Schedules](/hermes/orchestration/schedules) and [HTTP triggers](/hermes/orchestration/http-triggers) both reference a **single pipeline** to run. Multiple schedules or triggers can point at the same pipeline. **Run pipeline** from the dashboard targets one pipeline as well. [Variables](/hermes/orchestration/variables) are resolved when a run is planned (including manual runs), before agent jobs are created or invoked.
