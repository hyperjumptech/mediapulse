**Variables** are workspace-level named values. They are not tied to a single pipeline; any step’s **input** or **config** JSON can reference them so you do not hard-code secrets or environment-specific strings in every pipeline.

## Fields

- **Key**: Unique identifier (for example `OPENAI_API_KEY` or `BASE_URL`). Used inside `{{...}}` placeholders.
- **Value**: Plain text for normal variables. For **secret** variables, the value is stored encrypted; the UI never shows the decrypted secret after save.
- **Note**: Optional operator-facing comment.
- **Secret**: When enabled, the value is treated as sensitive; decryption at run time requires the worker/scheduler secret configuration.

## Substitution syntax

Use double curly braces with the key name:

```text
{{MY_VARIABLE_KEY}}
```

Whitespace inside the braces is trimmed (`{{ KEY }}` resolves the same as `{{KEY}}`).

Substitution walks **all string values** in step `input` and `config` JSON recursively. If a key is missing from the variables table, the placeholder is **left unchanged** so you can spot unresolved references in logs or payloads.

## Runtime behavior

When a [schedule](/hermes/orchestration/schedules) or other orchestration path plans a pipeline run, the scheduler loads variables, resolves `{{KEY}}` values (decrypting secrets when configured), and then validates and enqueues agent jobs. The same substitution applies to [HTTP trigger](/hermes/orchestration/http-triggers) runs.

## Dashboard

The **Variables** section provides list, search, create, edit, and delete. Editing a secret only replaces the stored value when you enter a new one; leaving the value blank keeps the previous ciphertext.
