## Purpose

agent-auth-api is a Hono server that manages **API keys** (create, list, get, update, delete, deactivate, reactivate), issues **short-lived JWT tokens** for agent invocation, and exposes **verification endpoints** for other services. **Agents, agent-data-api, and agent-registry-api** all verify the **same invocation JWT** via `POST /api/verify` (see `@workspace/agent-auth-client` `verifyTokenViaAuthApi`). `POST /api/verify-api-key` is for callers that present a raw API key (e.g. dashboard flows), not for agent→data-api traffic.

## Features

- **POST /api/verify** — **JWT-only** invocation verification. Accepts `Authorization: Bearer <jwt>`. Verifies signature and expiry. Used by agents to verify that the caller (Hermes/hermes-worker) is authorized. Requires `AGENT_AUTH_JWT_SECRET`.
- **POST /api/verify-api-key** — API-key verification for service callers. Accepts `Authorization: Bearer <api_key>`. Looks up hashed key in DB. Used where raw keys are required (e.g. some dashboard routes); **not** used for agent-data-api or agent-registry-api bearer auth (those use JWT verification above).
- **POST /api/token** — Issue a short-lived JWT (e.g. 15 min) for agent invocation. Accepts **`Authorization: Bearer <HERMES_INTERNAL_API_KEY>`** (preset shared with Hermes dashboard and worker; timing-safe compare to env) **or** a dashboard API key whose hash is stored in the DB with purpose **`domain_integration`** (or legacy **`scheduler`**). Requires `AGENT_AUTH_JWT_SECRET` and, for the preset path, `HERMES_INTERNAL_API_KEY`. Hermes dashboard and worker use the preset only to mint JWTs; they never send it to agents.
- **API key CRUD** — Create, retrieve (list + by id), update, delete API keys. In practice, **admins create API keys in the Hermes dashboard** (which calls this API). Create accepts optional **purpose** (`general`, `scheduler`, `run_pipeline`, `domain_integration`). Use **`domain_integration`** for Mediapulse and agent auto-register token minting.
- **Deactivate / reactivate** — Soft-disable keys without deleting. Revoking a **domain_integration** key stops that caller from obtaining new tokens after the next refresh.
- **Temporary admin auth** — API key management is protected by HTTP Basic Auth (`TEMP_ADMIN_USERNAME` / `TEMP_ADMIN_PASSWORD`) until a proper admin flow exists.

## Key routes

| Method | Path                           | Description                      |
| ------ | ------------------------------ | -------------------------------- |
| POST   | `/api/verify`                  | Verify JWT (invocation only)     |
| POST   | `/api/verify-api-key`          | Verify API key (service callers) |
| POST   | `/api/token`                   | Issue short-lived JWT            |
| POST   | `/api/api-keys`                | Create API key                   |
| GET    | `/api/api-keys`                | List API keys                    |
| GET    | `/api/api-keys/:id`            | Get one API key                  |
| PATCH  | `/api/api-keys/:id`            | Update API key                   |
| DELETE | `/api/api-keys/:id`            | Delete API key                   |
| POST   | `/api/api-keys/:id/deactivate` | Deactivate                       |
| POST   | `/api/api-keys/:id/reactivate` | Reactivate                       |

## Environment

- **AGENT_AUTH_JWT_SECRET** (required) — Secret for signing and verifying short-lived JWTs. Required for POST /api/token and POST /api/verify. Use a long random value (e.g. 32+ chars) in production.
- **HERMES_INTERNAL_API_KEY** — Preset bearer for Hermes dashboard/worker token minting (same value those services use). Optional only if you never use the preset path (not recommended for normal Hermes deployments).

## Port

- **8080** (default from `env.PORT`).
