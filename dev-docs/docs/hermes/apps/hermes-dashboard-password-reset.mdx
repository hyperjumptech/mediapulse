# Hermes dashboard — admin password reset

Operators can use **Forgot password** on the login page when they are locked out. The flow is email-based (Resend) and does not reveal whether an address is registered.

## Environment variables

Configure these in `packages/hermes/env` (see `env.example`):

| Variable | Purpose |
| -------- | ------- |
| `HERMES_DASHBOARD_PUBLIC_URL` | Public base URL of the dashboard (no trailing slash). Default `http://localhost:3001` for local dev. |
| `HERMES_RESEND_API_KEY` | Resend API key. If unset, tokens may still be created but no email is sent (local dev). |
| `HERMES_RESEND_FROM` | Resend `from` address. Required together with the API key to deliver mail. |

Rebuild env after changes: `pnpm build --filter @hermes/env`.

## Behaviour

- Reset links expire after **1 hour** and are **single-use**.
- Submitting forgot-password always shows the same success copy (anti-enumeration).
- After a successful reset, **`credentialVersion`** on the user increments so **all** existing dashboard sessions for that user stop working until they log in again.
- Rate limits are enforced **in-process** (per Node instance): forgot flow per email, reset completion per token hash. Multiple replicas do not share counters; add edge or Redis limiting if you need global caps.

## Logs

Structured log events (via `@workspace/logger`) include `hermes_admin_forgot_password_*` and `hermes_admin_reset_password_*` — search for these prefixes in application logs. Raw reset tokens and passwords are not logged.
