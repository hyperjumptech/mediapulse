## Purpose

This page documents **`@hermes/env`** — type-safe environment variables for **Hermes** apps (dashboard, worker, agent-auth-api, agent-registry-api) and the orchestration database. Values are generated from `packages/hermes/env/env.example` and `env.hermes-worker.example` (T3 Env / env-to-t3).

Never use `process.env` directly; import from `@hermes/env` or the documented subpath (e.g. `@hermes/env/hermes-worker` for the worker).

## Usage

```ts
import { env } from "@hermes/env";
const dbUrl = env.DATABASE_URL;
```

## Build

After changing any `env*.example` under `packages/hermes/env`, run `pnpm build` in `packages/hermes/env` to regenerate TypeScript output. Sensitive values must **not** use the `NEXT_PUBLIC_` prefix (server-only).

## Consumers

Hermes apps use `@hermes/env` (and `@hermes/env/hermes-worker` for the worker). **hermes-worker** requires `PG_DATAQUEUE_DATABASE` for the scheduler; DataQueue migrations are run from that app (`pnpm --filter @hermes/worker run migrate-dataqueue`).

## Product and agent env

Mediapulse apps, agents, and other product packages use **`@mediapulse/env`** — see **[Mediapulse → Packages](/mediapulse/packages)** (and per-agent subpaths such as `@mediapulse/env/agents-data-collection`). For how the two env layers fit deployment and local dev, see [Development](/guide/development) and [Hermes–Mediapulse integration](/integration).
