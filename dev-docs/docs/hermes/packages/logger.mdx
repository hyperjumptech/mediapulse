## Purpose

`@workspace/logger` exports a **Pino logger** configured with **redaction** for authorization headers, cookies, API keys, passwords, tokens, and PII (e.g. email). Used by all APIs and agents so logs stay safe.

## Exports

- **`logger`** — Default Pino instance (level from `LOG_LEVEL`, default `info`).
- **`pino`** — Pino constructor for custom instances.
- **`Logger`** — Type from `pino`.
- **`slimPinoLogger`** — Recommended Hono middleware: slim access logs via `slimHonoPinoHttpLoggerOptions`, with **`GET /health`** completion logs suppressed (load-balancer noise).
- **`slimHonoPinoHttpLoggerOptions`** — `hono-pino` `http` bindings used by `slimPinoLogger`: logs method, path, optional Hermes correlation headers (`x-job-id`, `x-execution-id`, etc.), and response status only (no full header dumps).
- **`shouldSkipHttpAccessLog`**, **`normalizeHttpAccessLogPath`** — Helpers for health-check access-log suppression (mainly for tests and custom wiring).
- **`buildDefaultRootLogger`**, **`isLogPrettyEnabled`**, **`pickHermesCorrelationHeadersForAccessLog`** — Building blocks and helpers (mainly for tests and advanced wiring).

## Human-readable output (local / debugging)

Set **`LOG_PRETTY=1`** (or `true` / `TRUE`) to send logs through **`pino-pretty`** (multiline, colorized timestamps). Default remains **one JSON line per log** for production and log aggregators. Applies to every process that imports the default `logger` (agents, Hono APIs, Hermes worker, and other consumers).

## Redaction paths

Includes `req.headers.authorization`, `*.password`, `*.token`, `*.apiKey`, `email`, and similar. Redacted values are replaced with `[REDACTED]`.

## Consumers

Hermes, Dashboard, agent-auth-api, agent-data-api, agent-registry-api, content-generation, data-collection, delivery (often via hono-pino middleware).
