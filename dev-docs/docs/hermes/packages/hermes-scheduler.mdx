## Purpose

`@hermes/scheduler` holds the **scheduler logic** used by Hermes: querying due schedules, executing them (expand params via an injected hook, invoke agents, record runs), and computing next run times. Hermes (Next.js) uses only `computeNextRunAt` for the dashboard; the long-running **hermes-worker** app uses the full API for the DataQueue `check_schedules` job.

## Exports

- **Due schedules:** `getDueSchedules`, `DueSchedule`, `GetDueSchedulesDb`
- **Execution:** `executeSchedule`, `ExecuteScheduleDeps`
- **Planning (shared):** `planPipelineInvocations` resolves variables, validates step input/config against agent schemas, and builds invocation waves; `substituteVariables` / `substituteInString` implement `{{KEY}}` replacement. Used by schedule execution, HTTP trigger execution in the worker, and manual **Run pipeline** in the dashboard (which then calls agents inline).
- **Next run:** `computeNextRunAt`, `ScheduleForNextRun`
- **Step input expansion:** `expandStepInputs` is injected via `ExecuteScheduleDeps` (runtime implementation in worker; syntax in `@hermes/step-input-syntax`).
- **Agent invocation:** `invokeAgent`, `AgentEndpointSchema`, `AgentEndpoint`, `InvokeAgentHttpClient`

## Consumers

- **Hermes dashboard** — Schedule create/update routes import `computeNextRunAt` and `ScheduleForNextRun`; manual pipeline run and HTTP trigger invoke routes use `planPipelineInvocations`.
- **hermes-worker** — Job handlers import `getDueSchedules`, `executeSchedule`, `executeHttpTrigger` (via `planPipelineInvocations`), and types to run the scheduler.

## Dependencies

`@hermes/orchestration-database`, `cron-parser`, `zod`. No HTTP client; callers pass an `InvokeAgentHttpClient` (e.g. `got`) when calling `executeSchedule` or `invokeAgent`.
