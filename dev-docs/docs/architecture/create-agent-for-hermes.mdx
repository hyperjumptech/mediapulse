Hermes **invokes agents** by sending an HTTP **POST** with a typed body (`input` + `config`) and a short-lived **JWT** from **agent-auth-api**. Agents are small HTTP services; they do not poll Hermes. The contract between scheduler and agent is documented in [Agent–Hermes contract](/architecture/agent-hermes-contract).

## 1. Scaffold a new agent (this repo)

From the repo root:

```bash
pnpm gen:agent
```

Or: `pnpm turbo gen agent --args my-agent` (kebab-case name). Then install, build env, and run **`./setup-agent-env.sh <agent-name>`** so `.env.local` gets **`DOMAIN_INTEGRATION_API_KEY`** (Hermes **`domain_integration`** key) and URLs. Step-by-step: [Generate a new agent](/mediapulse/apps/agents/generate-agent).

The template is based on **ticker-echo** (`apps/mediapulse/agents/ticker-echo`): `createAgentApp` from [`@workspace/agent-runtime`](/hermes/packages/agent-runtime), Zod schemas, and a `run` function.

## 2. Implement schemas and `run`

1. Define **`inputSchema`** (required) and optionally **`configSchema`** for static step configuration.
2. Pass them to **`createAgentApp`**; the runtime validates each request and exposes **GET `/schemas`** as JSON Schema for **agent-registry-api**.
3. Implement **`run({ input, config, token })`** and return a result that matches the envelope described in [Agent–Hermes contract — Response body](/architecture/agent-hermes-contract#response-body-agent--hermes).

Use **`token`** to call **agent-data-api** from [`@workspace/agent-data-api-client`](/hermes/packages/agent-data-api-client) when the agent needs persisted run data.

## 3. Environment variables

Agents read typed config from **`@mediapulse/env`** (never raw `process.env`). Typical variables:

| Variable                         | Role                                                                                                          |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **`AGENT_AUTH_API_URL`**         | agent-auth-api base URL (JWT verification).                                                                   |
| **`AGENT_REGISTRY_URL`**         | agent-registry-api base URL (e.g. `http://localhost:8082`).                                                   |
| **`AGENT_PUBLIC_URL`**           | URL where Hermes can reach this agent (must match how you run the service).                                   |
| **`DOMAIN_INTEGRATION_API_KEY`** | Hermes **domain_integration** API key — used to mint a JWT for **registry** registration (and related flows). |

Per-agent env is scaffolded under **`packages/mediapulse/env`** (`env.agents.<name>`). See [Generate a new agent — After generation](/mediapulse/apps/agents/generate-agent#after-generation-install-and-env).

## 4. Register with the agent registry

Hermes needs **metadata** (endpoint, version, **inputSchema** / **configSchema**) to validate schedules and pipeline steps.

- **Automatic:** pass **`autoRegister`** from `createAgentApp` options when **`AGENT_REGISTRY_URL`**, **`DOMAIN_INTEGRATION_API_KEY`**, **`AGENT_PUBLIC_URL`**, and **`AGENT_AUTH_API_URL`** are set; the agent POSTs to the registry on startup.
- **Manual:** POST to **agent-registry-api** with a JWT and the same schema payload (you can GET your agent’s `/schemas`).

Details: [Agent–Hermes contract — Auto-registration](/architecture/agent-hermes-contract#auto-registration-on-startup) and [agent-registry-api](/hermes/apps/agent-registry-api).

## 5. Use the agent in Hermes

1. Ensure the agent process is running and reachable at **`AGENT_PUBLIC_URL`**.
2. Confirm registration in the registry (or logs after startup).
3. In the Hermes dashboard, add the agent to a **pipeline step**, set **step config** if the agent defines a config schema, and create **schedules** whose **params (JSON)** match the agent’s **input schema**. Use **Variables** and `{{VAR_KEY}}` in config/params where needed ([Agent–Hermes contract — Variables](/architecture/agent-hermes-contract#variables-in-config-and-params)).
