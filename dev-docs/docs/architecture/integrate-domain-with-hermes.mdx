**Domain integration** means: your product exposes an HTTP API that implements the shared **Hermes domain contract**, and you **register** that service with Hermes so the orchestration layer knows its `baseUrl`, capabilities, and (optionally) **dashboard manifest** for `table-v1` pages. Hermes does **not** connect to your product database for these features; it loads registration from the **orchestration** database and calls your API.

For how Hermes and Mediapulse split apps and databases, start with [Hermes and Mediapulse domains](/architecture/domains).

## What you implement

| Concern                     | What Hermes calls                                                                                     |
| --------------------------- | ----------------------------------------------------------------------------------------------------- |
| **Step-input expansion**    | `POST /v1/expand-step-inputs` (and optionally `POST /v1/preview-expansion`)                           |
| **Hermes dashboard tables** | For each `table-v1` manifest page: `GET …/meta`, list, and optional CRUD under the page’s `apiPrefix` |

Schemas and client types live in [`@hermes/domain-contract`](/hermes/packages/hermes-domain-contract). The dashboard’s routing and HTTP shapes are described in [Hermes domain integration dashboard pages](/architecture/hermes-domain-integration-pages).

## Prerequisites

- A **Hermes API base URL** (e.g. `https://hermes.example.com` or `http://localhost:3001` in dev).
- A **domain integration API key** from Hermes (**Domain integrations → Create**): use the same value as **`DOMAIN_INTEGRATION_API_KEY`** for registration and agent flows, and set **`DOMAIN_INTEGRATION_KEY`** to the integration key string; see [Getting Started](/getting-started).
- **JWT (recommended):** Hermes mints short-lived JWTs via agent-auth-api **`POST /api/token`** using the **decrypted per-integration API key** from the orchestration DB (or **`HERMES_INTERNAL_API_KEY`** for strictly internal minting). Your domain API should verify with agent-auth-api **`POST /api/verify`** (see `AGENT_AUTH_API_URL` on the domain service). Create the integration in **Domain integrations** so the secret is stored and decrypted for outbound calls.

## Registration

1. **Start your domain HTTP service** on a stable **public `baseUrl`** (Hermes must reach it from the dashboard/worker).
2. **POST** to Hermes:

   `POST {HERMES_API_URL}/api/domain-integrations/register`

   Body must satisfy `registerDomainIntegrationRequestSchema` in the domain contract: at minimum **integration key**, **name**, **`baseUrl`**, optional **capabilities** (e.g. expansion, preview), and optional **`dashboard`** manifest for `table-v1` pages.

3. Hermes persists the row in the **orchestration** database (`DomainIntegration`). After a successful registration, the Hermes dashboard can show sidebar links and proxy table-v1 requests to `{baseUrl}`.

If registration fails or the integration is inactive, Hermes omits those sections or returns errors for missing routes.

## Environment variables (typical)

**On the domain service (caller):**

- **`HERMES_API_URL`** — Hermes origin used for `POST /api/domain-integrations/register`.
- **`DOMAIN_INTEGRATION_API_KEY`** — Bearer token for registration (the key shown once when the admin created the integration).

**On Hermes (already configured in deployment):**

- **`HERMES_INTERNAL_API_KEY`** — Master key for encrypting integration API keys at rest and for strictly internal **`POST /api/token`** minting.
- **`AGENT_AUTH_API_URL`** — Base URL of agent-auth-api for minting and verification.

Exact names for Mediapulse’s **`domain-api`** are listed in [domain-api (Mediapulse)](/mediapulse/apps/domain-api).

## Dashboard `table-v1` pages

To expose CRUD/list UIs in the Hermes dashboard under `/dashboard/{integrationKey}/{pathSegment}`:

1. Implement the **table-v1 HTTP surface** for your resource (meta, list, optional create/update/delete) under a chosen **`apiPrefix`**.
2. Add a matching entry to **`dashboard.pages`** in the registration payload (`template: "table-v1"`, `pathSegment`, `label`, columns, etc.).
3. Align **auth** with Hermes (JWT via agent-auth-api, or leave `AGENT_AUTH_API_URL` unset on the domain service only for local dev).

Full route table and sequence diagrams: [Hermes domain integration dashboard pages](/architecture/hermes-domain-integration-pages).
