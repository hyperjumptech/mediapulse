## System overview

**Hermes** (Next.js) is the orchestration dashboard: pipelines, schedules, API keys. It integrates with the **Mediapulse domain API** for data-source expansion and for domain-backed UI. **hermes-worker** runs the DataQueue scheduler and invokes agents over HTTP with short-lived JWTs.

**Mediapulse** provides **agent-data-api** (agent persistence), **domain-api** (Mediapulse DB + Hermes contract), **user-registration**, and the **agents** under `apps/mediapulse/agents/*`.

**Databases:** Two Prisma packages (`@hermes/orchestration-database` and `@mediapulse/database`) may share one PostgreSQL server with different schemas or use **separate databases**. DataQueue lives in its own schema (`dataqueue`); migrate it from **hermes-worker**.

For which app owns what, see [Hermes and Mediapulse domains](/architecture/domains). The default pipeline agent set includes `query-analysis`, `data-collection`, `analysis`, `content-generation`, and `delivery` (ports vary; see [Agents](/mediapulse/apps/agents/content-generation)).

## Flow

1. **Hermes** serves the dashboard and schedule/pipeline CRUD. The **scheduler** runs in **hermes-worker** (DataQueue), not inside the Next.js process.
2. **hermes-worker** enqueues `check_schedules` on a cron; it expands step inputs (via the registered **domain API** when needed) and invokes each agent step with `POST` + `Authorization: Bearer <jwt>`.
3. **Agents** verify the JWT via **agent-auth-api**, run their logic, and call **agent-data-api** with the **same forwarded JWT** for persistence.
4. **agent-registry-api** stores agent metadata for Hermes discovery; agents register with a **JWT** (often minted at startup with a scheduler key).
5. **PostgreSQL** holds orchestration tables, Mediapulse tables, and the DataQueue schema. Run Prisma migrations per package; DataQueue migrations: `pnpm --filter @hermes/worker run migrate-dataqueue`.
