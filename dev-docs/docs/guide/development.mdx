From a clean clone, you will install dependencies, start Postgres (Docker), run the bootstrap script to migrate databases and create an admin user, then start the dev servers with `pnpm dev`.

## Quick start (interactive, recommended)

```bash
docker-compose up -d
./dev-setup-local.sh
pnpm dev
```

Open **http://localhost:3001** when `pnpm dev` is up.

The setup script prompts for your admin email/password and then automatically:

- bootstraps env files/symlinks
- generates and writes `AGENT_AUTH_JWT_SECRET`
- sets `AGENT_AUTH_API_URL`
- runs DB + DataQueue migrations
- creates an admin user
- generates **`HERMES_INTERNAL_API_KEY`** (if missing) for Hermes worker, dashboard, and agent-auth-api
- creates one **domain_integration** API key and writes **`DOMAIN_INTEGRATION_API_KEY`** to Mediapulse env and to all agents’ `.env.local` (JWT minting, registry registration, and domain-api → Hermes self-registration)

## Quick start (non-interactive / automation)

```bash
docker-compose up -d
./dev-setup-local.sh --non-interactive --admin-email dev@example.com --admin-password "ChangeMe123!"
pnpm dev
```

Optional flags:

- `--agent-auth-api-url http://localhost:8080`
- `--local-dev-api-key-name "Local dev Mediapulse & agents"` (or deprecated alias `--domain-integration-key-name`)
- `--jwt-secret "<your-secret>"` (if omitted, the script generates one)
- `--skip-install` (use when dependencies are already installed)
- `--skip-migrations` (use when DB schema is already up to date)
- `--skip-admin` (use when admin user, **`HERMES_INTERNAL_API_KEY`**, and Mediapulse **`DOMAIN_INTEGRATION_API_KEY`** are already set)

## Prerequisites

- **Node.js 22+**
- **pnpm 10.4+** (`corepack enable && corepack prepare pnpm@latest --activate`)
- **Docker**
- **Bun** (optional; used by some local dev servers)

Use **pnpm** for install/scripts.

## What the setup script runs

`./dev-setup-local.sh` executes these steps in order:

1. `pnpm install` (unless `--skip-install`)
2. `./dev-bootstrap.sh`
3. Writes **`AGENT_AUTH_JWT_SECRET`**, **`AGENT_AUTH_API_URL`**, and ensures **`HERMES_INTERNAL_API_KEY`** in **`packages/hermes/env/.env`** (generates with `openssl` if missing or too short), then `pnpm --filter @hermes/env build && pnpm --filter @mediapulse/env build`
4. Prisma migrations + client generation in `packages/hermes/orchestration-database` and `packages/mediapulse/database` (unless `--skip-migrations`)
5. `pnpm --filter @hermes/worker run migrate-dataqueue:dev` (unless `--skip-migrations`)
6. `pnpm create:admin ...` in `apps/hermes/dashboard` (unless `--skip-admin`)
7. `pnpm seed-local-domain-integration ...` in `apps/hermes/dashboard` — creates a **pending** domain integration row (encrypted API key in DB), same as the dashboard wizard (unless `--skip-admin`)
8. Writes **`DOMAIN_INTEGRATION_ID`** and **`DOMAIN_INTEGRATION_API_KEY`** (plaintext once) to **`packages/mediapulse/env/.env`** (unless `--skip-admin` or integration already existed)
9. Writes the same vars to all `apps/mediapulse/agents/*/.env.local` (unless `--skip-admin` / same caveat as step 8)

### Services and ports

| Service                  | Port | Description                                    |
| ------------------------ | ---- | ---------------------------------------------- |
| hermes (dashboard)       | 3001 | Pipelines, schedules, domain integrations      |
| user-registration        | 3002 | Next.js app                                    |
| agent-auth-api           | 8080 | API key CRUD, verify, issue short-lived tokens |
| agent-data-api           | 8081 | Agent data storage                             |
| agent-registry-api       | 8082 | Agent registry                                 |
| data-collection agent    | 4001 | Mediapulse agent                               |
| content-generation agent | 4002 | Mediapulse agent                               |
| delivery agent           | 4003 | Mediapulse agent                               |
| ticker-echo agent        | 4010 | Minimal test agent                             |
| article-analysis agent   | 4011 | Mediapulse agent (KG analysis) — invoke `input`: `tickerId` (required); optional `reanalyze` (default false); optional `timeWindow` with ISO `start` / `end`; optional `maxBatchSize` (positive int). When `reanalyze` is true, Hermes must send at least one of `timeWindow` bounds or `maxBatchSize`. Uses `AGENT_DATA_API_URL` + bearer token like other agents. |
| domain-api (Mediapulse)  | 8090 | Hermes domain integration API (default in dev) |
| hermes-worker            | —    | Background worker (no HTTP port)               |

Optional **knowledge-graph** pipeline agents (**query-analysis**, **analysis**) may use other ports when deployed; see [Knowledge Graph](/mediapulse/knowledge-graph/knowledge-graph) and [Agents](/mediapulse/apps/agents/content-generation).

## Optional: Third-party API keys

For pipeline stages that read third-party keys from env (e.g. data collection, some KG agents), add the keys to the env file your Mediapulse apps load (typically **`packages/mediapulse/env/.env`**, merged or symlinked per `./dev-bootstrap.sh`). Delivery uses Hermes Agent config for Resend (see below).

| Variable         | Used by                 | Where to get it                  |
| ---------------- | ----------------------- | -------------------------------- |
| `JINA_API_KEY`   | data-collection         | [Jina.ai](https://jina.ai)       |
| `SERPER_API_KEY` | data-collection         | [Serper.dev](https://serper.dev) |
| `OPENAI_API_KEY` | KG agents when deployed | [OpenAI](https://openai.com)     |

**Delivery (Resend):** configure `resendApiKey` and `resend.from` on the **delivery Agent config** in Hermes (variables/secrets), not in this env file.

**Article analysis:** configure the **article-analysis** agent in Hermes with `openaiApiKey` (required). Optional tuning: `openaiModel`, `maxOutputTokens`, `maxContentChars`, per-article caps `maxEntitiesPerArticle` / `maxRelationsPerArticle`, per-run caps `maxEntitiesPerRun` / `maxRelationsPerRun`, and `postChunkRelationBatchSize` for POST chunking (each chunk’s body includes endpoint entities so relation names resolve in one `analysis.create` transaction). Mention rows use `maxArticleEntitiesPerArticle`, `maxArticleEntitiesPerRun`, and `postChunkArticleEntityBatchSize` for `articleEntities` POST batching after entities/relations are committed.

## Optional: Agent auto-registration

To let agents register with the registry on startup, set in each agent’s **`apps/mediapulse/agents/<name>/.env.local`**:

- `AGENT_REGISTRY_URL` (e.g. `http://localhost:8082`)
- `DOMAIN_INTEGRATION_ID` / `DOMAIN_INTEGRATION_API_KEY` (from **Domain integrations**; `./dev-setup-local.sh` seeds the same as the dashboard wizard)
- `AGENT_PUBLIC_URL` (e.g. `http://localhost:4001` for data-collection)

## Troubleshooting

**503 "Token issuance not configured"** — hermes-worker calls agent-auth-api to get a short-lived token; the auth API returns 503 when it has no JWT secret. Fix: open **`packages/hermes/env/.env`** (or the merged env your bootstrap script produces), set **`AGENT_AUTH_JWT_SECRET`** to a long random string (e.g. run `openssl rand -base64 32` and paste the output). Save the file, then **restart agent-auth-api and hermes-worker** (or stop and run `pnpm dev` again). If the var is missing or shorter than 16 characters, token issuance is disabled.

| Problem                             | Check                                                                                                                                                                                                                                                  |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| DB connection errors                | Docker is running (`docker-compose up -d`), `ORCHESTRATION_DATABASE_URL` in **`packages/hermes/env/.env`** and `MEDIAPULSE_DATABASE_URL` in **`packages/mediapulse/env/.env`** match your Postgres (see `./dev-bootstrap.sh` for how they are linked). |
| hermes-worker can’t get token / 403 | **`HERMES_INTERNAL_API_KEY`** must match on worker, dashboard, and agent-auth-api (not **`DOMAIN_INTEGRATION_API_KEY`**).                                                                                                                              |
| Agent auto-registration 401         | Re-run `./dev-setup-local.sh` or ensure **`DOMAIN_INTEGRATION_API_KEY`** / **`DOMAIN_INTEGRATION_ID`** match the **Domain integrations** entry in Hermes (same API secret and integration id as in the dashboard).                                     |
| Agent returns 401                   | Auth API is running (8080); **`AGENT_AUTH_API_URL`** is set where the agent loads env; the token or key is valid and not revoked.                                                                                                                      |
| Env var not picked up               | Edit **`packages/hermes/env/.env`** / **`packages/mediapulse/env/.env`** (or an app’s `.env.local`). Restart the app or `pnpm dev`.                                                                                                                    |
| DataQueue / cron errors             | Run **`pnpm --filter @hermes/worker run migrate-dataqueue:dev`** once.                                                                                                                                                                                 |

## Pull requests (code quality and Cursor rules)

- **`pnpm code-quality:affected`** — run before opening a PR when you only changed part of the monorepo. Uses Turbo `--affected` for build, lint, type-check, and tests, then merges coverage and runs Prettier. Set `TURBO_SCM_BASE=origin/main` (or your PR base) if Turbo cannot infer the comparison ref locally.
- **`pnpm code-quality`** — full workspace type-check, lint, tests with coverage, merged coverage report, and Prettier check. CI runs this scope on **push to `main`** and **`workflow_dispatch`**; PR CI uses affected checks instead (see [Production](/guide/production)).
- **`pnpm format:check:changed -- --base origin/main --head HEAD`** — Prettier on changed files only (what PR CI uses for formatting).
- **`pnpm cursor:review -- --base origin/main --head HEAD`** — fast diff check against `.cursor/rules` (heuristics only; not a substitute for `code-quality`).
- **AI review (optional)** — `pnpm ai:review` with `CURSOR_REVIEW_BASE_SHA` / `CURSOR_REVIEW_HEAD_SHA` and `OPENAI_API_KEY`; GitHub Actions can post an advisory comment when `OPENAI_API_KEY` is configured as a repo secret.
