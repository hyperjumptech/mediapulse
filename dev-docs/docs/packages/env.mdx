## Purpose

`@workspace/env` provides **type-safe environment variables** generated from `env.example` (and per-agent example files) using env-to-t3. Never use `process.env` directly; import from `@workspace/env` or a subpath.

## Exports

- **`.`** — Main app env (from `env.example`).
- **`./agents-content-generation`** — Env for content-generation agent.
- **`./agents-data-collection`** — Env for data-collection agent.
- **`./agents-delivery`** — Env for delivery agent.

## Usage

```ts
import { env } from "@workspace/env";
const dbUrl = env.DATABASE_URL;
```

```ts
import { env } from "@workspace/env/agents-data-collection";
const apiKey = env.SERPER_API_KEY;
```

## Build

After changing any `env*.example` file, run `pnpm build` in `packages/env` to regenerate the TypeScript output. Sensitive values must **not** use the `NEXT_PUBLIC_` prefix (server-only).

## Consumers

All apps and agents; each uses the main export or the appropriate agent subpath. **hermes-worker** requires `PG_DATAQUEUE_DATABASE` for the scheduler; DataQueue migrations are run from that app (`pnpm --filter hermes-worker run migrate-dataqueue`).

## Agent-specific overrides (development)

Agents share `packages/env/.env` but can override **per-agent** values via **`.env.local`** in each agent app:

- **`PORT`** — e.g. 4001 (data-collection), 4002 (content-generation), 4003 (delivery).
- **`AGENT_PUBLIC_URL`** — URL where that agent is reachable (e.g. `http://localhost:4003`).
- **`AGENT_REGISTRY_API_KEY`** — optional; can differ per agent when auto-registering with the registry.

`./dev-bootstrap.sh` symlinks each agent’s `.env` to the shared env and runs `merge-agent-env.sh` to create/update `apps/agents/<name>/.env.local` from `env.agents.<name>.example`. Dev scripts load `.env` then `.env.local`, so overrides in `.env.local` apply only to that agent. Edit `apps/agents/delivery/.env.local` (and similar) to set `AGENT_PUBLIC_URL` and `AGENT_REGISTRY_API_KEY` for local development.
