## System overview

Hermes is the central orchestrator: it runs pipelines (cron or manual), each step invoking an agent by HTTP with a bearer token. Agents call the **agent-data-api** for reading/writing pipeline data and the **agent-auth-api** for token verification. The **agent-registry-api** is used to register agents. All persistent data lives in PostgreSQL via the shared **database** package.

## Flow

1. **Hermes** runs pipeline steps (e.g. data-collection → content-generation → delivery) and sends `POST` requests with `{ tickerId }` and `Authorization: Bearer <apiKey>` to each agent.
2. **Agents** validate the body, verify the token via **agent-auth-api**, run their logic, and call **agent-data-api** to read/write ticker/newsletter/subscriber data.
3. **agent-registry-api** stores agent metadata; Hermes (or tooling) can register agents there.
4. **PostgreSQL** holds users, API keys, tickers, pipelines, agents, and all pipeline-produced data.
