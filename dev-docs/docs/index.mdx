## What is this monorepo?

The codebase is organized around two main systems:

- **Hermes** — **Agent orchestration**: dashboard, worker/scheduler, auth API, registry API, and the **orchestration** database (pipelines, schedules, domain integrations, **admin** users). External domains integrate over HTTP; Hermes does not embed product databases for those features.
- **Mediapulse** — **Product data and agents**: **agent-data-api**, **domain-api** (integration with Hermes + Mediapulse DB), user registration, and HTTP **agents** under `apps/mediapulse/agents/*`, backed by the **Mediapulse** database (tickers, newsletters, knowledge graph, and related tables).

**[Hermes–Mediapulse integration](/integration)** explains how Mediapulse plugs into Hermes (JWTs, registration, expansion, dashboard `table-v1` in this repo).

## Stack

- **Monorepo:** pnpm workspaces, Turborepo
- **Hermes apps:** Next.js dashboard, Bun worker; Bun + Hono for agent-auth-api and agent-registry-api
- **Mediapulse apps:** Bun + Hono for agent-data-api and domain-api; Next.js for user-registration; agents as small HTTP services with `@workspace/agent-runtime`
- **Database:** PostgreSQL with Prisma (`@hermes/orchestration-database` and `@mediapulse/database`)
- **Env:** `@hermes/env` and `@mediapulse/env` (T3 Env / env-to-t3), not raw `process.env`

## Running the project

For installation, environment setup, database migrations, and how to run each app, see [Development](/guide/development).

Quick reference:

- **Database:** `docker-compose up` then run Prisma migrate/generate for `packages/hermes/orchestration-database` and `packages/mediapulse/database` (see Development).
- **Hermes dashboard:** `pnpm dev --filter=@hermes/dashboard` (port **3001**)
- **APIs:** `pnpm dev --filter=@hermes/agent-auth-api`, `pnpm dev --filter=@mediapulse/agent-data-api`, `pnpm dev --filter=@hermes/agent-registry-api`
- **Agents:** `apps/mediapulse/agents/<name>` — each has its own `.env.local` when needed
