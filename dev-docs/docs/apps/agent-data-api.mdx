## Purpose

agent-data-api is a Hono server that exposes **data endpoints** used by the agents (query-analysis, data-collection, analysis, content-generation, delivery). All routes are protected by **bearer auth**; the token is verified via `@workspace/agent-auth-client` against agent-auth-api.

## Features

- **Bearer auth** — Every request must include `Authorization: Bearer <api_key>`. API keys are verified via agent-auth-api `POST /api/verify-api-key` (agents use admin-issued API keys to call this service).
- **Query-analysis** — GET/POST endpoints for reading ticker KG context and writing generated search queries.
- **Content-generation** — GET/POST for content-generation data (e.g. store/retrieve generated newsletter content).
- **Data-collection** — GET/POST for data-collection data (e.g. store/retrieve collected pages/sources).
- **Analysis** — GET/POST endpoints for unscored articles, KG vocabulary/context, and bulk relevance writes.
- **Delivery** — GET/POST for delivery data (e.g. newsletter content + subscribers for sending).

Agents call this API through `@workspace/agent-data-api-client`, which centralizes endpoint paths, request typing, and response parsing with shared contract schemas.

## Key routes

| Method | Path                      | Description                                    |
| ------ | ------------------------- | ---------------------------------------------- |
| GET    | `/api/query-analysis`     | Get query-analysis context by `tickerId`       |
| POST   | `/api/query-analysis`     | Upsert generated search queries                |
| GET    | `/api/content-generation` | Get content-generation data (e.g. by tickerId) |
| POST   | `/api/content-generation` | Store content-generation payload               |
| GET    | `/api/data-collection`    | Get data-collection data                       |
| POST   | `/api/data-collection`    | Store data-collection payload                  |
| GET    | `/api/analysis`           | Get analysis payload (e.g. unscored items)     |
| POST   | `/api/analysis`           | Store analysis/KG and relevance results        |
| GET    | `/api/delivery`           | Get delivery data (newsletter + subscribers)   |
| POST   | `/api/delivery`           | Store delivery payload                         |

## Port

- **8081** (default from `env.PORT`).

## Workspace dependencies

- `@workspace/agent-auth-client` — `verifyTokenViaAuthApi` for bearer (invocation JWT) auth.
- `@workspace/agent-data-api-contract` — Shared Zod schemas and inferred endpoint types.
- `@workspace/agent-data-api-client` — Typed SDK used by agents.
- `@workspace/agent-types` — Shared data-collection request/body schemas.
- `@workspace/api-utils` — Error helpers.
- `@workspace/env` — Environment (including `AGENT_AUTH_API_URL`).
- `@workspace/database` — Prisma for reading/writing agent data.
- `@workspace/logger` — Pino logger.

## Endpoint change workflow

When the API surface changes (new endpoint, removed endpoint, or request/response changes), use this order:

1. Update schemas in `@workspace/agent-data-api-contract`.
2. Update `apps/agent-data-api` handlers and services.
3. Update `@workspace/agent-data-api-client` methods.
4. Update agent consumers.
5. Update tests and run `pnpm code-quality`.

See `.cursor/skills/agent-data-api-endpoints/SKILL.md` for the detailed checklist.
