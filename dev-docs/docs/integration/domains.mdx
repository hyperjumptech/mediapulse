The repo is split into two **product domains**. You can host both on one PostgreSQL server using **separate schemas**, or run **separate databases** by pointing `ORCHESTRATION_DATABASE_URL` and `MEDIAPULSE_DATABASE_URL` at different URLs. Env packages and source trees stay aligned with each domain.

## Domain overview

Hermes keeps orchestration state in **one database**; Mediapulse keeps product and agent-run data in **another**. Cross-domain integration is **JWT-backed agent calls** from the worker and **HTTP to the registered domain API** (in this repo, **Mediapulse `domain-api`**) for expansion and dashboard-backed tables (via `@hermes/domain-contract`).

## Hermes domain (orchestration)

**Role:** Pipelines, schedules, API keys, agent registry metadata, **admin** users for the dashboard, and the worker that runs scheduled jobs. Hermes does **not** store newsletter, ticker, or knowledge-graph tables. For **data-source expansion** and for dashboard UIs that need Mediapulse data, Hermes calls the **Mediapulse domain API** over HTTP (see [How the domains connect at runtime](#how-the-domains-connect-at-runtime) below).

| Area                                                     | Location / package                                                          |
| -------------------------------------------------------- | --------------------------------------------------------------------------- |
| Dashboard & pipeline UI                                  | `apps/hermes/dashboard` (`@hermes/dashboard`)                               |
| Background worker & DataQueue                            | `apps/hermes/worker` (`@hermes/worker`)                                     |
| Auth API (JWT + API keys)                                | `apps/hermes/agent-auth-api` (`@hermes/agent-auth-api`)                     |
| Agent registry API                                       | `apps/hermes/agent-registry-api` (`@hermes/agent-registry-api`)             |
| Orchestration DB (Prisma)                                | `packages/hermes/orchestration-database` (`@hermes/orchestration-database`) |
| Env (T3)                                                 | `packages/hermes/env` (`@hermes/env`)                                       |
| Scheduler library                                        | `packages/hermes/scheduler` (`@hermes/scheduler`)                           |
| Domain integration contract (HTTP client for domain API) | `packages/hermes/domain-contract` (`@hermes/domain-contract`)               |

## Mediapulse domain (product data & agents)

**Role:** Ticker/newsletter/knowledge-graph data, **Mediapulse users** (subscribers), agent-data persistence API, user-facing registration app, operational **agents** (HTTP services invoked by Hermes), and the **domain API** that serves Mediapulse-specific expansion and Hermes dashboard `table-v1` resources (including **Mediapulse users** CRUD).

| Area                                                               | Location / package                                                                                |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| Agent data API (agents read/write run data)                        | `apps/mediapulse/agent-data-api` (`@mediapulse/agent-data-api`)                                   |
| Domain integration API (expansion + dashboard HTTP for Mediapulse) | `apps/mediapulse/domain-api` (`@mediapulse/domain-api`)                                           |
| User registration (Next.js)                                        | `apps/mediapulse/user-registration` (`@mediapulse/user-registration`)                             |
| Operational agents                                                 | `apps/mediapulse/agents/*` (e.g. `@mediapulse/data-collection`, `@mediapulse/content-generation`) |
| Mediapulse DB (Prisma)                                             | `packages/mediapulse/database` (`@mediapulse/database`)                                           |
| Env (T3)                                                           | `packages/mediapulse/env` (`@mediapulse/env`)                                                     |
| Hermes↔DB expansion helpers                                        | `packages/mediapulse/hermes-integration` (`@mediapulse/hermes-integration`)                       |

## Shared across domains

These are **not** “owned” by a single domain; both sides depend on them:

| Concern                                      | Package                                                                           |
| -------------------------------------------- | --------------------------------------------------------------------------------- |
| Agent HTTP runtime, bearer auth              | `@workspace/agent-runtime`                                                        |
| Agent–data API contract & SDK                | `@workspace/agent-data-api-contract`, `@workspace/agent-data-api-client`          |
| Auth client (verify JWT with agent-auth-api) | `@workspace/agent-auth-client`                                                    |
| Logging, API helpers, UI kit                 | `@workspace/logger`, `@workspace/api-utils`, [`@workspace/ui` (docs)](/shared/ui) |

## How the domains connect at runtime

1. **Pipeline runs:** Hermes / hermes-worker mints a short-lived JWT via **agent-auth-api** and calls **agents** (Mediapulse apps). Agents call **agent-data-api** with the same JWT.
2. **Data-source expansion:** Scheduler asks the registered **domain API** (`expand-step-inputs`, `preview-expansion`); that service uses **Mediapulse** Prisma via `@mediapulse/hermes-integration`, not a direct Hermes→DB shortcut. See [Data source expansion](/integration/data-source-expansion).
3. **Dashboard tables for Mediapulse entities:** Hermes renders routes from the integration manifest and proxies list/meta/CRUD to the **domain API** (e.g. `/v1/hermes-dashboard/...`), not to `@mediapulse/database` from the Next.js server. See [Domain integration dashboard](/hermes/domain-integration-dashboard) for the Next.js layout, routes, and HTTP flow.

For auth flows and diagrams, see [Communication between parts](/integration/communication). For step input and schemas, see [Agent–Hermes contract](/hermes/agent-hermes-contract).

## User identities

**Hermes `User`** rows are **dashboard / admin** accounts (API keys, login). **Mediapulse `MediapulseUser`** rows are **end users / newsletter subscribers** (`user_ticker` references them). Do not treat orchestration users as newsletter recipients.
