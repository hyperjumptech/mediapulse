This page describes **Mediapulse-specific** integration with Hermes. For the generic domain contract and registration flow, see [Integrate a domain with Hermes](/hermes/integrate-domain-with-hermes). For the two-database map, see [Hermes and Mediapulse domains](/integration/domains).

## domain-api as the registered integration

**`apps/mediapulse/domain-api`** (`@mediapulse/domain-api`) implements the Hermes **domain integration** contract and **self-registers** on startup (`POST {HERMES_API_URL}/api/domain-integrations/register`). Hermes stores the row in the orchestration database; the dashboard and worker then call that service’s `baseUrl` for:

- **Step-input expansion** — `POST /v1/expand-step-inputs` (and optional preview).
- **`table-v1` dashboard pages** — List/meta/CRUD under `/v1/hermes-dashboard/...` for each manifest page.

Implementation detail and code layout: [domain-api](/mediapulse/apps/domain-api). Expansion against Mediapulse Prisma uses [`@mediapulse/hermes-integration`](/mediapulse/packages/mediapulse-hermes-integration).

## Environment variables (Mediapulse side)

Exact names for **`domain-api`** (including `MEDIAPULSE_API_URL`, `HERMES_API_URL`, `DOMAIN_INTEGRATION_API_KEY`, `AGENT_AUTH_API_URL`) are documented on [domain-api](/mediapulse/apps/domain-api). **`DOMAIN_INTEGRATION_API_KEY`** and **`DOMAIN_INTEGRATION_ID`** must match the integration created in the Hermes dashboard (**Domain integrations**).

Admins copy the generated API key once into Mediapulse and agent env (see [Development](/guide/development) for local bootstrap).

## Hermes dashboard: examples that use the Mediapulse integration

This repo typically registers an integration whose **integration id** is `mediapulse` (configurable). Routes are **`/dashboard/{integrationId}/{pathSegment}`**.

- **Pipeline run helpers** — Some Hermes UI flows resolve the registered **Mediapulse** integration (manifest + `baseUrl` from orchestration) to list tickers via the same `table-v1` list pattern as other domain tables (`fetchAllTickersForPipelineRun` in `domain-dashboard.ts`). See [Domain integration dashboard](/hermes/domain-integration-dashboard).

- **Ticker import (IDX JSON)** — When the manifest registers a `json-file-upload` custom action for tickers, the dashboard shows an import card and POSTs to the domain API; Mediapulse runs [`@mediapulse/idx-tickers-importer`](/mediapulse/packages/idx-tickers-importer) on the service side.

- **Search queries, entity types, relation types** — Product-owned tables exposed under the integration manifest (e.g. `/dashboard/mediapulse/search-queries`) are served by `domain-api`, not by the Hermes Next.js server reading the Mediapulse database.

- **Data source expansion templates** — Saved template rows live in the **Hermes orchestration** database (`DataSourceExpansionTemplate`); preview and runtime expansion still go through `domain-api`. See [Data source expansion](/integration/data-source-expansion).

- **KG dev seeding** — Vocabulary seeding uses Mediapulse DB scripts; pipeline/schedule seeds for KG workflows run from `apps/hermes/dashboard`. See [Knowledge Graph](/mediapulse/knowledge-graph/knowledge-graph#schedule-configuration-default-seeds).
