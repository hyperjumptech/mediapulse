Hermes **invokes agents** by sending an HTTP **POST** with a typed body (`input` + `config`) and a short-lived **JWT** from **agent-auth-api**. Agents are small HTTP services; they do not poll Hermes. The scheduler–agent contract is documented in [Agent–Hermes contract](/hermes/agent-hermes-contract).

## Cursor: use the Generate agent skill

In Cursor, you can use the **Generate agent** skill so the AI follows the full workflow for you. Invoke it by name (e.g. **`/generate-agent`** or by referencing the **generate-agent** skill). The skill instructs the AI to:

1. Run `pnpm gen:agent` (or `pnpm turbo gen agent --args <agent-name>`).
2. Run `pnpm install` (with `--no-frozen-lockfile` if needed).
3. Run `./setup-agent-env.sh <agent-name>` so the agent gets `.env`/`.env.local` and `DOMAIN_INTEGRATION_API_KEY` (domain_integration) for auto-registration.

Use the skill when you want to create a new agent or add another package under **`apps/mediapulse/agents/`**.

## Command

From the repo root:

```bash
pnpm gen:agent
```

Or with the agent name to skip the prompt:

```bash
pnpm turbo gen agent --args my-agent
```

You will be prompted for an **agent name** in kebab-case (e.g. `my-agent`). The generator creates a new package under **`apps/mediapulse/agents/<name>/`** with name **`@mediapulse/<name>`** and wires **`packages/mediapulse/env`** (new `env.agents.<name>.example` and export).

The template matches **ticker-echo** (`apps/mediapulse/agents/ticker-echo`): **`createAgentApp`** from [`@workspace/agent-runtime`](/hermes/packages/agent-runtime), Zod schemas, and a **`run`** function.

## After generation: install and env

Run these steps after the generator succeeds:

1. **Install** — `pnpm install` (use `--no-frozen-lockfile` if the lockfile is frozen).
2. **Build** — `pnpm --filter @mediapulse/env build` so the new agent env export exists.
3. **Env and API key** — `./setup-agent-env.sh <agent-name>`. This:
   - Runs `dev-bootstrap.sh` so the agent gets `.env` and `.env.local` from `env.agents.<name>.example` (with the correct `PORT` and `AGENT_PUBLIC_URL`).
   - Copies `DOMAIN_INTEGRATION_API_KEY` into the agent's `.env.local` from another agent's `.env.local` or from **`packages/mediapulse/env/.env`**. If none exists, run **`./dev-setup-local.sh`** first, or from **`apps/hermes/dashboard`**: `pnpm seed-local-domain-integration <admin-email>`.

Optional flag for `setup-agent-env.sh`: `--no-bootstrap` (skip bootstrap if `.env` is already set up).

## Environment variables

Agents read typed config from **`@mediapulse/env`** (never raw `process.env`). Typical variables:

| Variable                         | Role                                                                                                                         |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **`AGENT_AUTH_API_URL`**         | agent-auth-api base URL (JWT verification; also used to mint a JWT for registry registration when using **`autoRegister`**). |
| **`AGENT_REGISTRY_URL`**         | agent-registry-api base URL (e.g. `http://localhost:8082`).                                                                  |
| **`AGENT_PUBLIC_URL`**           | URL where Hermes can reach this agent (must match how you run the service).                                                  |
| **`DOMAIN_INTEGRATION_API_KEY`** | Hermes **domain_integration** API key — used to mint a JWT for **registry** registration (and related flows).                |

Per-agent env is scaffolded under **`packages/mediapulse/env`** (`env.agents.<name>`). After `./setup-agent-env.sh`, ensure **`AGENT_REGISTRY_URL`** is set in `.env.local` if you want auto-registration and the example does not already include it.

## What gets created

- **`apps/mediapulse/agents/<name>/`** — New agent package with `package.json` `@mediapulse/<name>`, `src`, tests, and `turbo.json` (same pattern as `apps/mediapulse/agents/ticker-echo`).
- **`packages/mediapulse/env/`** — New `env.agents.<name>.example`, build script, and export `./agents-<name>`.
- **Root `package.json`** — New script `dev:agent-<name>` → `turbo dev --filter=@mediapulse/<name>`.

## Auto-registration with the agent registry

Hermes needs **metadata** (endpoint, version, **inputSchema** / **configSchema**) to validate schedules and pipeline steps.

Agents built with `createAgentApp` can **register themselves** with the agent-registry-api when they start. The generated `src/index.ts` passes **`autoRegister`** when these env vars are set:

- **`AGENT_AUTH_API_URL`** — Required for minting the registry JWT when **`autoRegister`** is enabled (if it is missing, registration is skipped and an error is logged).
- **`AGENT_REGISTRY_URL`** — URL of the agent-registry-api (e.g. `http://localhost:8082`).
- **`DOMAIN_INTEGRATION_API_KEY`** — Hermes **domain_integration** API key used to mint a JWT for registry registration (`./setup-agent-env.sh` gets or creates it and writes it to the agent's `.env.local`).
- **`AGENT_PUBLIC_URL`** — Public URL where the agent is reachable (e.g. `http://localhost:4010`). The env example sets this from `PORT`.

When all of the above are set, the agent POSTs its metadata and schemas to the registry on startup (fire-and-forget, with retries). If registration fails (e.g. registry unreachable), the error is logged and the agent keeps running. If any required value is missing, auto-registration is skipped and a warning is logged.

**Manual registration:** POST to **agent-registry-api** with a JWT and the same schema payload you can read from your agent’s **GET `/schemas`**. Details: [Agent–Hermes contract — Auto-registration](/hermes/agent-hermes-contract#auto-registration-on-startup) and [agent-registry-api](/hermes/apps/agent-registry-api).

## Customize your agent

1. **Input and config** — Define **`inputSchema`** (required) and optionally **`configSchema`** for static step configuration. Pass them to **`createAgentApp`**; the runtime validates each request and exposes **GET `/schemas`** as JSON Schema for **agent-registry-api**.
2. **Run logic** — Implement **`run({ input, config, token })`** and return a result that matches the envelope in [Agent–Hermes contract — Response body](/hermes/agent-hermes-contract#response-body-agent--hermes).
3. **Data API** — Use **`token`** to call **agent-data-api** from [`@workspace/agent-data-api-client`](/hermes/packages/agent-data-api-client) when the agent needs persisted run data.
4. **Env** — After `./setup-agent-env.sh`, the agent has `.env.local` with `PORT` and `DOMAIN_INTEGRATION_API_KEY`. Set `AGENT_REGISTRY_URL` in `.env.local` if you want auto-registration and the example does not already include it.

The minimal template is **ticker-echo**; the generator is based on it so you only define body, config, and what the agent does.

## Use the agent in Hermes

1. Ensure the agent process is running and reachable at **`AGENT_PUBLIC_URL`**.
2. Confirm registration in the registry (or logs after startup).
3. In the Hermes dashboard, add the agent to a **pipeline step**, set **step config** if the agent defines a config schema, and create **schedules** whose **params (JSON)** match the agent’s **input schema**. Use **Variables** and `{{VAR_KEY}}` in config/params where needed ([Agent–Hermes contract — Variables](/hermes/agent-hermes-contract#variables-in-config-and-params)).
