## Cursor: use the Generate agent skill

In Cursor, you can use the **Generate agent** skill so the AI follows the full workflow for you. Invoke it by name (e.g. **`/generate-agent`** or by referencing the **generate-agent** skill). The skill instructs the AI to:

1. Run `pnpm gen:agent` (or `pnpm turbo gen agent --args <agent-name>`).
2. Run `pnpm install` (with `--no-frozen-lockfile` if needed).
3. Run `./setup-agent-env.sh <agent-name>` so the agent gets `.env`/`.env.local` and `DOMAIN_INTEGRATION_API_KEY` (domain_integration) for auto-registration.

Use the skill when you want to create a new agent or add another package under **`apps/mediapulse/agents/`**.

## Command

From the repo root:

```bash
pnpm gen:agent
```

Or with the agent name to skip the prompt:

```bash
pnpm turbo gen agent --args my-agent
```

You will be prompted for an **agent name** in kebab-case (e.g. `my-agent`). The generator creates a new package under **`apps/mediapulse/agents/<name>/`** with name **`@mediapulse/<name>`** and wires **`packages/mediapulse/env`** (new `env.agents.<name>.example` and export).

## After generation: install and env

Run these steps after the generator succeeds:

1. **Install** — `pnpm install` (use `--no-frozen-lockfile` if the lockfile is frozen).
2. **Build** — `pnpm --filter @mediapulse/env build` so the new agent env export exists.
3. **Env and API key** — `./setup-agent-env.sh <agent-name>`. This:
   - Runs `dev-bootstrap.sh` so the agent gets `.env` and `.env.local` from `env.agents.<name>.example` (with the correct `PORT` and `AGENT_PUBLIC_URL`).
   - Gets or creates `DOMAIN_INTEGRATION_API_KEY` (**domain_integration**) and sets it in the agent's `.env.local`. The script reuses an existing key from another agent's `.env.local` or from **`packages/mediapulse/env/.env`**; if none exists, it can create one via Hermes `generate-api-key` with purpose `domain_integration` (requires `--admin-email` or `ADMIN_EMAIL` in **`packages/mediapulse/env/.env`**). If no key exists and no admin email is available, the script exits with instructions; run again with `--admin-email <email>` or after `./dev-setup-local.sh`.

Optional flags for `setup-agent-env.sh`: `--no-bootstrap` (skip bootstrap if `.env` is already set up), `--admin-email EMAIL`, `--key-name NAME`.

## What gets created

- **`apps/mediapulse/agents/<name>/`** — New agent package with `package.json` `@mediapulse/<name>`, `src`, tests, and `turbo.json` (same pattern as `apps/mediapulse/agents/ticker-echo`).
- **`packages/mediapulse/env/`** — New `env.agents.<name>.example`, build script, and export `./agents-<name>`.
- **Root `package.json`** — New script `dev:agent-<name>` → `turbo dev --filter=@mediapulse/<name>`.

## Auto-registration with the agent registry

Agents built with `createAgentApp` can **register themselves** with the agent-registry-api when they start. The generated `src/index.ts` passes **`autoRegister`** when these env vars are set:

- **`AGENT_REGISTRY_URL`** — URL of the agent-registry-api (e.g. `http://localhost:8082`).
- **`DOMAIN_INTEGRATION_API_KEY`** — Hermes **domain_integration** API key used to mint a JWT for registry registration (`./setup-agent-env.sh` gets or creates it and writes it to the agent's `.env.local`).
- **`AGENT_PUBLIC_URL`** — Public URL where the agent is reachable (e.g. `http://localhost:4010`). The env example sets this from `PORT`.

When all three are set, the agent POSTs its metadata and schemas to the registry on startup (fire-and-forget, with retries). If registration fails (e.g. registry unreachable), the error is logged and the agent keeps running. If any of the three is missing, auto-registration is skipped and a warning is logged.

## Customize your agent

1. **Input and config** — Edit `src/index.ts`: change the Zod `InputSchema` (and add `configSchema` if needed).
2. **Run logic** — Implement the `run` function; it receives `{ input, config, token }` and returns `Promise<AgentRunResult>` (e.g. `{ success: true }` or `{ success: false, message: "…" }`).
3. **Env** — After `./setup-agent-env.sh`, the agent has `.env.local` with `PORT` and `DOMAIN_INTEGRATION_API_KEY`. Set `AGENT_REGISTRY_URL` in `.env.local` if you want auto-registration and the example does not already include it.

The minimal template is **ticker-echo** (`apps/mediapulse/agents/ticker-echo`); the generator is based on it so you only define body, config, and what the agent does.
