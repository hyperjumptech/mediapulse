## Source quality v2

Relevance scoring stores five subscores in `article_relevance.score_breakdown`. Before source quality v2, `sourceQuality` was always **0.5**, so the weighted aggregate only used four live dimensions.

When Hermes sets **`useSourceQualityV2`: `true`**, the agent computes a real `sourceQuality` value per data source from three deterministic signals (no extra LLM call):

| Sub-signal | Default internal weight | What it measures |
| ---------- | ----------------------- | ---------------- |
| Host class | 0.5 | Publisher tier from URL hostname (suffix match) |
| Recency | 0.3 | Exponential decay from `publishedAt` or `createdAt` |
| Structural | 0.2 | Body length, paragraph breaks, shouting (uppercase ratio in body only) |

The combined score is clamped to `[0, 1]` and passed into `buildScoreBreakdownV1` as `signals.sourceQualityScore`. When the flag is off, the field is omitted and the breakdown still uses **0.5** — same math as before for `scoreBreakdownVersion` **1**.

### Host tiers (default suffix lists)

| Tier | Score | Example domains |
| ---- | ----- | ---------------- |
| tier1 | 0.9 | `reuters.com`, `bloomberg.com`, `apnews.com`, `wsj.com`, `ft.com`, `nytimes.com` |
| tier2 | 0.7 | `cnbc.com`, `marketwatch.com`, `barrons.com`, `forbes.com`, `businessinsider.com`, `seekingalpha.com`, `reuters.co.uk` |
| tier3 | 0.4 | `medium.com`, `substack.com`, `benzinga.com` |
| unknown | 0.5 | Everything else (`markets.reuters.com` matches `reuters.com`) |

Operator overrides **`sourceQualityHostTier1`**, **`sourceQualityHostTier2`**, and **`sourceQualityHostTier3`** **replace** the built-in list for that tier (they do not merge).

### Recency

`recencyScore = exp(-ageHours / halfLifeHours)` with default **`sourceQualityRecencyHalfLifeHours`: 72**. Age uses **`publishedAt`** when present, otherwise **`createdAt`**. If no usable date is available, recency is **0.5** (neutral).

### Structural cues

- **Length:** peak **1.0** between 1500–8000 characters; below 500 → **0.2**; above 15000 → **0.6**
- **Paragraphs:** rewards `\n\n` breaks (≥ 3 for full credit)
- **Shouting:** penalizes uppercase ratio **> 0.15** in the body (title excluded)

### Example breakdown computation

Suppose host class **0.9** (Reuters), recency **0.95** (2 hours old, 72h half-life), structural **0.88**:

```
sourceQuality = 0.5×0.9 + 0.3×0.95 + 0.2×0.88 ≈ 0.911
```

That value becomes `scoreBreakdown.sourceQuality`. The final relevance **`score`** still uses Hermes `relevanceWeight*` keys (default **0.2** each across five dimensions).

### Config knobs

| Key | Default | Meaning |
| --- | ------- | ------- |
| `useSourceQualityV2` | `false` | Enable real source-quality scoring |
| `sourceQualityRecencyHalfLifeHours` | `72` | Recency decay half-life |
| `sourceQualityHostTier1` | (built-in) | Optional tier-1 host suffix list override |
| `sourceQualityHostTier2` | (built-in) | Optional tier-2 override |
| `sourceQualityHostTier3` | (built-in) | Optional tier-3 override |

### Observability

Run summary field **`sourceQuality`** includes `tier1Sources`, `tier2Sources`, `tier3Sources`, `unknownHostSources`, `avgRecencyHours`, and `avgQualityScore`. With **`verbose`: `true`**, each source logs a per-row breakdown (`hostTier`, `recencyScore`, `structuralScore`, etc.).

### Upgrade path

Existing rows with `sourceQuality: 0.5` remain valid under **`scoreBreakdownVersion` 1** — only the source of that number changes when v2 is enabled. Bump breakdown version when you change canonical keys or weight semantics, not when turning on v2.

## Selection diversification

When **`useSelectionDiversification`: `true`**, the daily `selected: true` budget prefers distinct event clusters instead of pure top-K by score. Syndicated wires that share entities and near-identical headlines compete for one representative slot first; remaining budget still fills by score so slots are not wasted when only a few clusters exist.

### Adjacency rules (union-find)

Two eligible rows (`score >= relevanceMinScore`) merge into the same cluster when **either**:

| Signal | Default threshold | Rule |
| ------ | ----------------- | ---- |
| Entity overlap | `selectionEntityOverlapThreshold` **0.5** | Jaccard over normalized canonical names, aliases, and mention names |
| Title similarity | `selectionTitleSimilarityThreshold` **0.4** | Jaccard over 4-word lowercase title shingles |

Clustering is O(n²) on the batch (n ≤ `maxBatchSize`). No embeddings or LLM calls.

### Selection walk

1. Sort rows by score (desc), then newer `createdAt`.
2. **Phase 1:** Select the highest-scored row in each cluster (cluster representative) until budget is exhausted.
3. **Phase 2:** Fill any remaining budget with the next highest-scored eligible rows, including additional rows from clusters that already have a representative.

With **`useSelectionDiversification`: `false`**, `applyRelevanceSelection` runs unchanged (byte-identical to the legacy top-K path).

### Config knobs

| Key | Default | Meaning |
| --- | ------- | ------- |
| `useSelectionDiversification` | `false` | Enable event-cluster diversification |
| `selectionEntityOverlapThreshold` | `0.5` | Entity Jaccard merge threshold (higher → more clusters) |
| `selectionTitleSimilarityThreshold` | `0.4` | Title shingle Jaccard merge threshold |

### Observability

Run summary field **`selection`** reports `eligibleRows`, `clustersFormed`, `selectedAfterDiversification`, `suppressedAsDuplicates` (rows classic top-K would have taken but diversification skipped because they were not cluster representatives), and `largestClusterSize`.

Pair with **source quality v2**: the cluster representative is usually the highest-scored row, which tends to be the best outlet when `useSourceQualityV2` is on.
