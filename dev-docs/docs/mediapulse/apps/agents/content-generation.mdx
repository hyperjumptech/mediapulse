## Purpose

The content-generation agent takes **selected data sources** (scored by the analysis agent and served by agent-data-api) and produces a **newsletter** (subject, content, optional description) using OpenAI. It then stores the result via agent-data-api for the delivery agent to consume.

## Features

- **Input:** `tickerId` as a non-empty string (UUID or opaque Hermes ticker id). Receives bearer token from Hermes.
- **Fetches** selected high-relevance sources, resolved competitor names, and issuer aliases for the ticker from `GET /api/v1/content-generation` (rows where `article_relevance.selected = true` and scored today; competitors come from `COMPETITOR`/`SECTOR_PEER` edges off the ticker's KG anchor, see [KG competitor resolution](#kg-competitor-resolution)).
- **Calls OpenAI** via the Vercel AI SDK (`generateObject` from `ai` with `@ai-sdk/openai` provider) to generate structured **industry intelligence** newsletter JSON (subject, multi-section briefing, quick hits with `articleIndex` grounding). The API key, optional API base URL, and model id are **not** read from environment variables; they come from the **agent config** selected for the pipeline step in Hermes (Dashboard → Agent configs), so admins can manage credentials centrally (optionally using [variable expansion](/hermes/agent-hermes-contract#variables-in-config-and-params) for secrets).
- **Serializes** the validated object to plain text with the first-line marker `MP_NEWSLETTER` and deterministic `BEGIN … END` blocks. URLs are **never** taken from model text; they are injected from Hermes-selected sources using each `articleIndex`. Inline `(Article N)` markers that the model sometimes writes into bullet, quick-hit, or prose text are **stripped deterministically** at wire serialization — subscribers see citations only via the rendered `Read the full article: <url>` line. Prompt-side blocks (the brainstorm memo and numeric-anchor sidecar) intentionally keep `(Article N)` tags as LLM input and are not part of the email body. Legacy bodies without the marker (`EXECUTIVE SUMMARY` / `TOP N NEWS`) are unchanged for historical rows. The shared email package parses both shapes (see `@workspace/email-templates` `parseNewsletterBody`).
- **Retries** transient LLM failures (rate limits, 5xx errors, timeouts) using exponential backoff with optional jitter, up to `reliability.llmRetry.maxAttempts` (default 3). Non-retryable errors (auth, bad request, schema validation) short-circuit immediately.
- **Classifies errors** into structured outcome codes for diagnostics (see [Error taxonomy](#error-taxonomy) below).
- **Retries persist** errors (agent-data-api 5xx, 429, network timeouts) using exponential backoff up to `reliability.persistRetry.maxAttempts` (default 2, no jitter). Non-retryable 4xx client errors fail fast without retrying.
- **Stores** generated content via agent-data-api for the delivery agent.
- **Skips** with a clear message and outcome code `no_sources` if no data sources are found.
- **Skip-if-fresh** — Before calling OpenAI, checks whether a newsletter already exists for the ticker within today's freshness window (`freshness.timezone` calendar day). If fresh, the run is skipped with outcome code `skipped_fresh_newsletter_exists`. See [Freshness Behavior](/mediapulse/apps/agents/content-generation-freshness) for full semantics.

## Error taxonomy

Every run exit path maps to a canonical `OutcomeCode` (defined in `src/types/outcome.ts`):

| Code                              | Description                                                                                        |
| --------------------------------- | -------------------------------------------------------------------------------------------------- |
| `no_sources`                      | No data sources found; run skipped without calling OpenAI                                          |
| `skipped_fresh_newsletter_exists` | Fresh newsletter exists; run skipped (MP-CGA-006)                                                  |
| `openai_retry_exhausted`          | LLM returned retryable errors and all retries were exhausted                                       |
| `openai_non_retryable`            | LLM returned a non-retryable error (auth, bad request, etc.)                                       |
| `openai_invalid_response`         | LLM returned HTTP 200 but no structured object was produced                                        |
| `validation_failed`               | LLM output failed Zod schema validation (`TypeValidationError`)                                    |
| `persist_transient`               | agent-data-api returned 429 or 5xx on newsletter create and all persist retries were exhausted     |
| `persist_client_error`            | agent-data-api returned a non-retryable 4xx client error on newsletter create (no retry attempted) |

The `AgentRunResult` envelope returned to Hermes is unchanged: `{ success: false, message: "..." }` for all failure/skip paths. The `AgentOutcome` internal type (with `OutcomeCode` and `skipped` flag) is available for future diagnostic writes (MP-CGA-007). Persist retry logic uses `persistRetry` config (MP-CGA-009); the `stage` field in diagnostic records is `"persist"` for both persist outcome codes (MP-CGA-007).

## Source ranking

Before the LLM call, the agent can re-rank and diversify the truncated source list so the prompt is not dominated by one wire repeating the same lede. Ranking is **pre-LLM only** — no extra model cost, and `articleIndex` still refers to the numbered articles in the final prompt order.

### Composite score

Each candidate gets a deterministic score (higher is better):

```
score = relevanceWeight × (1 / (relevanceRank + 1))
      + recencyWeight × recencyFactor
      + tierWeight × tierFactor
      + lengthWeight × lengthFactor
```

| Component | Default weight | Factor                                                                                                |
| --------- | -------------- | ----------------------------------------------------------------------------------------------------- |
| Relevance | 0.45           | `1 / (rank + 1)` where rank 0 is the most relevant source from agent-data-api                         |
| Recency   | 0.25           | `exp(-hours / recencyHalfLifeHours)` clamped to [0, 1]; **neutral 0.5** when `publishedAt` is missing |
| Tier      | 0.20           | tier1 = 1.0, tier2 = 0.7, tier3 = 0.4, unknown = 0.2                                                  |
| Length    | 0.10           | `min(1, bodyChars / 1200)` — thin bodies under ~250 words score lower                                 |

Default half-life is **36 hours** (a 12h-old article ≈ 0.79, 36h ≈ 0.50, 72h ≈ 0.25).

### Host diversification

After sorting by score, a greedy pass picks sources while capping each host at `sourceRanking.maxPerHost` (default **2**). If every remaining host is at cap, spillover fills remaining slots in score order so the prompt is always full.

### Host tier table

Hand-maintained suffix list (longest match wins). Hosts not listed but with a normal TLD fall to **tier3**; bare IPs, `.xyz`, and unparseable URLs are **unknown**.

| Tier  | Example domains                                                                      |
| ----- | ------------------------------------------------------------------------------------ |
| tier1 | `reuters.com`, `bloomberg.com`, `ft.com`, `wsj.com`, `kontan.co.id`, `bisnis.com`, … |
| tier2 | `cnbcindonesia.com`, `detik.com`, `tempo.co`, `kompas.com`, `idnfinancials.com`, …   |
| tier3 | `medium.com`, `substack.com`, unlisted publishers with a recognizable TLD            |

Keep this table aligned with [article-analysis source quality](/mediapulse/apps/agents/article-analysis) — tier drift between agents is confusing in ops dashboards.

### Config

| Field                                | Default         | Description                                    |
| ------------------------------------ | --------------- | ---------------------------------------------- |
| `sourceRanking.enabled`              | `true`          | Set `false` to restore relevance-only ordering |
| `sourceRanking.maxPerHost`           | `2`             | Max articles per host in the prompt            |
| `sourceRanking.recencyHalfLifeHours` | `36`            | Recency decay half-life                        |
| `sourceRanking.weights.*`            | see table above | Per-component weights (each 0–1)               |

### Tuning workflow

- **Indonesian locals drowned out by global tier1 wires** — raise `weights.tier` or add local domains to tier1/tier2 via PR.
- **Breaking-news tickers** — lower `recencyHalfLifeHours` (e.g. 12) or raise `weights.recency`.
- **Slow-news / weekly tickers** — raise half-life toward 72h so yesterday’s context still scores well.

Each run logs `selectedHosts`, `hostTierDistribution`, and `recencyP50Hours` before the LLM call for week-over-week mix dashboards.

## Few-shot exemplars

Newsletter generation can prepend one or two hand-curated **voice exemplars** before the numbered articles. Exemplars are prose-formatted (not JSON) so the model calibrates tone, bullet length (~25–40 words), and creative `displayHeading` titles — not schema shape, which `generateObject` already enforces.

### What each exemplar teaches

| Exemplar bank id  | Sector tag   | Teaches                                                        |
| ----------------- | ------------ | -------------------------------------------------------------- |
| `industrial-INDX` | `industrial` | Grounded industrial prose, cited bullets, personality headings |
| `consumer-CONSM`  | `consumer`   | Consumer/financial voice, quick-hit density                    |

Fictional tickers and article titles — the live run must ground only in real sources.

### Selection heuristic

When `inputs.fewShot.sectorTag` is unset, the agent concatenates `tickerName`, `tickerSymbol`, and source titles and keyword-matches:

- **Consumer/financial exemplar** when text mentions `bank`, `finance`, `consumer`, `lending`, `deposits`, etc.
- **Industrial exemplar** otherwise

Set `inputs.fewShot.sectorTag` to pin a sector regardless of keywords. Set `inputs.fewShot.maxExemplars` to `2` to show both voices (~1500 prompt tokens each).

### Token budget

Each exemplar adds roughly **1500 prompt tokens**. If exemplars plus source summaries would exceed `context.maxTotalContextChars`, **sources drop from the end first** — exemplars are never removed. Ops logs include `exemplarsUsed`, `promptCharsAddedByExemplars`, and `sourcesDroppedForExemplarSpace`.

### Plagiarism fail-safe

After generation, local **Jaccard similarity** compares bullet text to the active exemplar. Overlap above **0.6** emits `newsletter_possibly_plagiarized_exemplar` in logs. The prompt disclaimer is the primary guard; detection is a fail-safe.

### Adding a new exemplar

1. Open a PR adding a full `IndustryNewsletterStructure` entry to `NEWSLETTER_EXEMPLAR_BANK` in `src/lib/newsletter-exemplars.ts`.
2. Assign a unique `id`, `sectorTag`, fictional `tickerSymbol`, and `sourceTitles`.
3. Keep every required section grounded in fictional `Article N` references so the model sees complete structure.
4. Document expected token cost in the PR (~1500 tokens per exemplar).
5. Extend selection tests if the new sector needs distinct keyword routing.

Default rollout: all quality passes ship **on** in an empty `{}` config; dial individual knobs back in Hermes to trade cost for latency.

## Two-pass generation

When `creativity.brainstorm.enabled` is true, the agent runs **two LLM calls** per newsletter:

1. **Brainstorm pass** (`generateText`) — a free-form editor's memo with six labeled sections: `HEADLINE THESIS`, `THREADS TO WEAVE`, `STANDOUT NUMBERS`, `WHAT CHANGED`, `WHAT TO WATCH`, and `TONE NOTE`. No JSON, no schema — the model commits to thesis, threads, numbers, and tone before formatting.
2. **Structured pass** (`generateObject`) — the existing industry briefing JSON, conditioned on the memo plus numbered articles (and optional few-shot exemplars on the structured pass only).

The structured user prompt prepends:

> Below is your editor's memo for this week. Use it as the spine for the briefing…

Exemplars from [Few-shot exemplars](#few-shot-exemplars) are **not** shown to the brainstorm pass — only the structured pass sees them.

### Why six memo sections

Each label forces a different cognitive mode (synthesis, expansion, concrete figures, comparison, forecast, voice). Free prose alone often skips "what changed" and "what to watch." The `TONE NOTE` line is the biggest qualitative lever — it sets sober vs contrarian vs technical register for the JSON pass.

### Config

| Field                           | Default                 | Description                            |
| ------------------------------- | ----------------------- | -------------------------------------- |
| `creativity.brainstorm.enabled` | `true`                  | Enable two-pass generation             |
| `creativity.brainstorm.model`   | `credentials.chatModel` | Cheaper model for the memo leg is fine |
| `brainstormMaxOutputTokens`     | `700`                   | Memos are short by design              |

### Cost and timeout

Expect roughly **2× prompt tokens** and **~1.3× completion tokens** versus single-pass. On brainstorm failure (transport, timeout, empty memo) the run **falls back to single-pass** — consumers still get a newsletter. If the brainstorm consumes more than **half** of `credentials.timeoutMs`, the memo is dropped for that run so the structured pass keeps enough budget.

### Observability

- Structured-pass tokens remain in `promptTokens` / `completionTokens` on the persisted newsletter row.
- Brainstorm tokens surface on the agent run `details`: `brainstormUsed`, `brainstormPromptTokens`, `brainstormCompletionTokens`.
- Logs: `Newsletter brainstorm pass complete`, `brainstorm_failed_fallback`, `brainstorm_slow_single_pass_fallback`.

### Rollout

Enable on one or two pilot tickers, watch yield and subjective quality for a week, then enable per ticker where briefing quality moves the product needle.

## Citation grounding

After the structured LLM call, the agent can walk every row with an `articleIndex` and verify that the cited article actually supports the claim. This is a **deterministic post-generation check** — no extra LLM or embedding cost.

### Overlap score

Each cited bullet is scored in `[0, 1]` using:

1. **3-gram Jaccard** over stopword-filtered tokens from the bullet vs. the article title plus the first 2000 characters of body (same stopword list as phrase link injection).
2. **Numeric bonus** (+0.2 by default, capped at 1.0) when the bullet contains digits and a matching number appears in the article text. Industry briefings live on figures — `$2.3B`, `12.4%`, etc. — so shared numbers are the strongest grounding signal.

Default minimum overlap is **0.18**. Rows below the threshold are handled per policy.

### Policies

| Policy   | Behavior                                                                                              |
| -------- | ----------------------------------------------------------------------------------------------------- |
| `warn`   | Observability only — structure unchanged; use for the first rollout week to size failure rate         |
| `unlink` | Clear `articleIndex` on optional bullets; prose ships without the implied citation link (**default**) |
| `drop`   | Remove the row entirely, subject to schema-floor protection                                           |

`quickHits` require `articleIndex` on every item — unlink is not valid. Failed quick hits can only be dropped or kept. When dropping would fall below `min(5)`, the row is **kept** and a `quickHits_ground_failed_keeping_item` warning is logged.

### Schema-floor protection

The walker never emits output that fails `industryNewsletterStructureSchema`. When a `drop` would violate a section minimum (`competitiveLandscape` min 2, `quickHits` min 5, etc.), drops are downgraded to `unlink` (or kept for quick hits). A `groundingFloorPreserved` log event records how many rows were protected.

### Config

| Field                               | Default  | Description                                   |
| ----------------------------------- | -------- | --------------------------------------------- |
| `citationGrounding.enabled`         | `false`  | Turn on post-generation citation verification |
| `citationGrounding.policy`          | `unlink` | `warn`, `unlink`, or `drop`                   |
| `citationGrounding.minOverlapScore` | `0.18`   | Minimum score to keep a citation              |
| `citationGrounding.numericBonus`    | `0.2`    | Bonus when bullet numbers match the article   |

### Observability

One rolled-up log line per run: `totalCitations`, `unlinked`, `dropped`, `floorPreserved`, `p50Overlap`, `p10Overlap`. Per-bullet reports are attached to the agent run result (`details.grounding`) — not logged at info level.

### Rollout

Start with `enabled: true, policy: 'warn'` for one week. Watch `p10Overlap` and tune `minOverlapScore`, then flip to `unlink`.

## Numeric anchors

Industry briefings lose signal when the model rounds or paraphrases figures. Numeric anchors extract concrete numbers from source bodies **before** the structured LLM call, show them to the model as a verbatim-quote sidecar, then audit every figure in the generated briefing.

### Regex bank

Deterministic patterns (no extra LLM cost) cover the highest-value units:

| Unit         | Examples                                    |
| ------------ | ------------------------------------------- |
| **currency** | `Rp 12.4 trillion`, `$2.3B`, `IDR 500 juta` |
| **percent**  | `12.4%`, `6,1%`                             |
| **count**    | `8 new branches`, `1,200 customers`         |
| **ratio**    | `3.5x`, `2 kali`                            |

Currency and percent matches get salience **1.0**; counts and ratios get **0.7**. `selectTopAnchors` keeps at most `perArticleCap` (default **5**) per article and `totalCap` (default **25**) overall, sorted by salience then earlier position in the body.

### Prompt sidecar

When `numericAnchors.enabled` is true, the user prompt includes a block immediately above the article list:

```text
VERBATIM FIGURES AVAILABLE FROM SOURCES:
- Rp 12.4 trillion (Article 3)
...
When quoting a figure in a bullet, use the EXACT string above. Do not paraphrase or round.
```

### Post-generation audit

After generation (and optional [citation grounding](#citation-grounding)), the agent walks every prose line, bullet, and quick hit, re-runs the same regex bank, and checks each figure as a **substring** of some source title+body. Figures with no source match land in `unmatchedFigures`.

**Anchor coverage** is the headline quality metric:

`anchorCoverageRatio = anchorsQuotedVerbatim / anchorsTopSelected`

A briefing that quotes 8 of 18 top anchors is numerically grounded; one that quotes 1 of 18 is competent prose but thin on signal.

### Unmatched policy

| Policy  | Behavior                                                                    |
| ------- | --------------------------------------------------------------------------- |
| `warn`  | Observability only — briefing text unchanged (**default**)                  |
| `strip` | Replace unmatched tokens with `[figure removed]` and log `numeric_stripped` |

`strip` can produce awkward grammar, so operators usually run `warn` for a week, watch coverage and unmatched counts, then enable `strip` on tickers where `anchorCoverageRatio` is already above ~50%.

### Config

| Field                            | Default | Description                                        |
| -------------------------------- | ------- | -------------------------------------------------- |
| `numericAnchors.enabled`         | `false` | Extract anchors and run the figure audit           |
| `numericAnchors.perArticleCap`   | `5`     | Max anchors per article in the sidecar             |
| `numericAnchors.totalCap`        | `25`    | Max anchors overall in the sidecar                 |
| `numericAnchors.unmatchedPolicy` | `warn`  | `warn` or `strip` for figures missing from sources |

### Observability

One info log per run: `anchorsExtracted`, `anchorsTopSelected`, `anchorsQuotedVerbatim`, `anchorCoverageRatio`, `unmatchedFigures` (count). Run `details.numericAnchors` carries the same rollup for dashboards.

### Rollout

Enable `warn` on one or two pilot tickers for a week. Track `anchorCoverageRatio` trend. Where coverage stays above 50% and unmatched counts are low, try `strip` on those tickers only.

## Subject line scoring

The structured JSON pass emits one subject line. That is high leverage for open rate but leaves no comparison. When `subjectLine.enabled` is true, a small sidecar LLM call requests 3–8 stylistically mixed candidates (declarative, numeric, curiosity, contrast), each with a 50–110 character preheader. A deterministic scorer picks the winner.

### Scoring axes

| Axis               | Default weight | What it measures                                                            |
| ------------------ | -------------- | --------------------------------------------------------------------------- |
| **lengthFit**      | 0.20           | Triangular curve peaking at ~42 characters (mobile inbox sweet spot)        |
| **tickerPresence** | 0.15           | Symbol or company name in the subject vs generic references                 |
| **curiosityGap**   | 0.25           | Question marks, numbers, contrast words, curiosity verbs; clickbait penalty |
| **novelty**        | 0.20           | `1 - max Jaccard` vs subjects from the last 7 days (floor 0.6)              |
| **readability**    | 0.20           | Shorter mean syllables per word score higher                                |

Weights are tunable per ticker via `subjectLine.weights`.

### Original-wins-on-tie

The subject from the main structured pass competes as **candidate 0** with a preheader derived from the first 110 characters of `industryPulse.prose`. If a generated candidate ties the original score, the **original wins** — same voice as the body.

### Recent subject history

`run.ts` loads the last 7 days of subjects via `contentGenerationNewslettersRecent.get({ tickerId, days: 7 })`. Network or 404 failures fall back to `recentSubjects: []` (novelty = 1.0 for all candidates). The run never blocks on history.

### Config

| Field                        | Default                 | Description                              |
| ---------------------------- | ----------------------- | ---------------------------------------- |
| `subjectLine.enabled`        | `false`                 | Enable candidate generation and scoring  |
| `subjectLine.candidateCount` | `5`                     | Target number of LLM candidates (3–8)    |
| `delivery.subjectLine.model` | `credentials.chatModel` | Sidecar model (cheaper tier is fine)     |
| `subjectLine.weights.*`      | see axes above          | Per-axis weights for the composite score |

### Observability

One info log per run with `originalSubject`, `winnerSubject`, `winnerScore`, `originalScore`, `candidateCount`, and `candidateScores`. Run `details.subjectLine` and `details.preheader` surface the winner for delivery preview text ([delivery preview optimization](../delivery) when plan 50 lands).

### Non-goals

This is **not** per-recipient A/B testing. The agent picks one winner per newsletter. Production variant testing is a delivery-side concern.

### Rollout

Enable on one pilot ticker, aggregate a week of ranked logs into a “subject style winners by ticker” view, then tune `subjectLine.weights` for tickers where declarative lines underperform.

## Wire format: optional sections

The `MP_NEWSLETTER` wire format supports a variable set of body sections. Only sections present on the resolved briefing with at least one row are emitted by the serializer.

### Mandatory vs omittable

| Section                   | Status                                                                    |
| ------------------------- | ------------------------------------------------------------------------- |
| `industry-pulse`          | Always emitted. It is the newsletter spine and carries no citation.       |
| `competitive-landscape`   | Omittable. Absent when the field is `undefined` on the resolved briefing. |
| `deals-and-movements`     | Omittable.                                                                |
| `regulatory-policy-watch` | Omittable.                                                                |
| `disruptors-or-tech`      | Omittable. The bullets variant is also suppressed when it has zero rows.  |
| `quick-hits`              | Omittable.                                                                |

### Representation of absence

Absence is always represented by the section field being `undefined` on `IndustryNewsletterResolved`, never by an empty `bullets` or `items` array. A zero-row section is a contradiction the serializer refuses to emit.

### Parser and renderer behavior

The wire parser (`parseIndustryNewsletterWire`) accepts any in-order subset of sections. Omitting a middle section never shifts the survivors. A wire containing only `industry-pulse` parses to `{ format: 'industry', sections: [industry-pulse] }`. The renderer maps over whatever sections the parser returns and has a defensive guard that renders nothing for any zero-bullet section that arrives.

### LLM schema is unchanged

The LLM output schema (`industryNewsletterStructureSchema`) is not relaxed. The model is still asked to produce all sections with their current minimums. Optionality lives only in the post-LLM resolved and wire layers. The pruning pass in plan 70 (`require-citation-and-prune-sections`) is what will produce partial newsletters in practice by dropping sections that have no grounded content.

## Cross-run dedup

Subscribers should not see the same bullet on Monday, Wednesday, and Friday when nothing new happened. Cross-run dedup adds **longitudinal memory** across the last N days of persisted newsletters.

### Two-arm strategy

| Arm            | When                                 | What it does                                                                                                                    |
| -------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| **Preventive** | Before the structured LLM call       | Injects the 15 most recent bullets into the user prompt under `AVOID REPEATING THESE RECENT BULLETS (last {{windowDays}} days)` |
| **Detective**  | After generation (post subject-line) | Jaccard 3-gram similarity walk over every bullet and quick hit vs up to **200** recent bullets                                  |

Both arms use the same tokenizer as citation grounding — deterministic, no embedding cost.

### Policies

| Policy | Behavior                                                                              |
| ------ | ------------------------------------------------------------------------------------- |
| `warn` | Log near-duplicates only (**default**)                                                |
| `mark` | Prepend `[follow-up] ` to flagged bullets (visible to subscribers)                    |
| `drop` | Remove the row, subject to schema-floor protection (downgrades to `mark` when needed) |

Default `minSimilarity` is **0.55**. Tune per ticker after a week of `warn` logs.

### Low-information day

When more than `lowInfoDayThreshold` (default **50%**) of today's bullets match recent history, the run sets `lowInformationDay: true` on agent `details`. This plan does **not** auto-skip delivery — wire a Hermes gate if operators want skip-publish on quiet days.

### Config

| Field                               | Default | Description                                       |
| ----------------------------------- | ------- | ------------------------------------------------- |
| `crossRunDedup.enabled`             | `false` | Enable both preventive and detective arms         |
| `crossRunDedup.windowDays`          | `14`    | Lookback for recent bullets (daily briefings)     |
| `crossRunDedup.minSimilarity`       | `0.55`  | Jaccard threshold for near-duplicate              |
| `crossRunDedup.policy`              | `warn`  | `warn`, `mark`, or `drop`                         |
| `crossRunDedup.lowInfoDayThreshold` | `0.5`   | Fraction of flagged bullets → `lowInformationDay` |

### Observability

One info log per run: `recentBulletCount`, `bulletsCompared`, `nearDuplicates`, `droppedByDedup`, `markedByDedup`, `p50Similarity`, **`p95Similarity`**, `lowInformationDay`. Watch **p95Similarity** week over week — a climbing trend means the ticker is repeating itself.

### Rollout

1. `enabled: true`, `policy: warn` for one week — size false-positive rate.
2. Move to `mark` on tickers with duplicate complaints.
3. Use `drop` only where terse briefings are acceptable and duplicate rates stay high.

Composes with [self-critique](#self-critique): critique redundancy is **within** today's briefing; cross-run dedup is **across** prior briefings.

## Style polish

A deterministic pass removes common LLM tics from prose, bullets, quick hits, summaries, and quotes — no extra model call. It runs **after** [self-critique](#self-critique) and **before** [citation grounding](#citation-grounding) so overlap scores reflect content words, not warmup fillers like "It's worth noting that".

### Rule bank

| Tier               | Rules                                                                                                                                                                                                                               |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **safe** (default) | Filler removal (`It's worth noting that`, `Importantly,`, `As mentioned earlier`, …), hedge collapse (`could potentially` → `could`), register-mix cleanup (strip `dan` / `atau` / `yang` / `dengan` from English-dominant bullets) |
| **aggressive**     | Above plus overused-word replacement when `robust`, `significant`, `noteworthy`, or `compelling` appears in **3+** bullets (at most **one** replacement per word per briefing)                                                      |

Filler rules preserve capitalization on the following word (`Importantly, the regulator` → `The regulator`).

### Config

| Field                    | Default | Description                                                                          |
| ------------------------ | ------- | ------------------------------------------------------------------------------------ |
| `polish.enabled`         | `false` | Enable the polish pass                                                               |
| `polish.tier`            | `safe`  | `safe` or `aggressive`                                                               |
| `polish.disabledRuleIds` | `[]`    | Skip specific rule ids (e.g. `filler-its-worth-noting`) without turning off the pass |

### Observability

One info log per run: `polishTier`, `rulesFired` (per-rule counts), `totalReplacements`. Rising counts for a rule id week over week signal model habit drift.

### Rollout

1. Enable `polish.enabled` with `tier: safe` for all tickers.
2. After rule firings stabilize, opt high-chatter tickers into `tier: aggressive`.
3. Pin noisy rules off per ticker via `disabledRuleIds` in Hermes config.

Composes with [cross-run dedup](#cross-run-dedup): dedup catches **across** briefings; polish catches **within**-briefing word over-use and filler.

## Self-critique

After structured generation and optional numeric anchor audit, the agent can run **one bounded critic pass** that scores each bullet on four dimensions:

| Dimension            | What it catches                                                 |
| -------------------- | --------------------------------------------------------------- |
| **specificity**      | Cargo-cult prose vs concrete claims                             |
| **citationStrength** | Whether the cited article is the best source (lexical re-check) |
| **redundancy**       | Near-duplicate bullets in the same briefing                     |
| **readerValue**      | Whether an operator would act on the line                       |

The critic returns `drop`, optional `suggestedRewrite`, and numeric scores. The system applies at most `dropFraction × total` actions (default **20%**). With `preferRewriteOverDrop: true` (default), rewrites keep briefing density; drops are the fallback.

### Schema-floor invariant

Critique **never** emits output that fails `industryNewsletterStructureSchema`. Drops that would violate section minimums (`competitiveLandscape` min 2, `quickHits` min 5, etc.) are blocked and logged as `critiqueFloorPreserved`. Rewrites only mutate text — they are not constrained by the floor.

### Config

| Field                                  | Default                 | Description                                  |
| -------------------------------------- | ----------------------- | -------------------------------------------- |
| `selfCritique.enabled`                 | `false`                 | Enable the critic pass                       |
| `selfCritique.dropFraction`            | `0.2`                   | Max fraction of bullets rewritten or dropped |
| `selfCritique.minBulletCount`          | `8`                     | Skip critique below this bullet count        |
| `quality.selfCritique.critiqueModel`   | `credentials.chatModel` | Critic model (cheaper tier is fine)          |
| `selfCritique.critiqueMaxOutputTokens` | `1500`                  | Output cap for the critic call               |
| `selfCritique.preferRewriteOverDrop`   | `true`                  | Use `suggestedRewrite` before dropping       |

### Deadline guard

When wall-clock since run start exceeds **70%** of `credentials.timeoutMs` after structured generation, critique is skipped — the briefing continues through polish and grounding without critic scores. Run details include `critiqueSkippedDueToBudget: true`.

### Pipeline order

`structured JSON` → numeric anchor audit (optional) → self-critique (optional) → style polish (optional) → citation grounding (optional) → subject line (optional) → cross-run dedup (optional) → URL attachment → require-citation pruning (optional) → wire format.

### Observability

Logs include `critique: { bulletsRated, bulletsRewritten, bulletsDropped, floorPreserved, promptTokens, completionTokens, p50Specificity, p50ReaderValue }`. Track `p50Specificity` and `p50ReaderValue` week over week in yield dashboards — a drop often means source quality or prompt drift loosened citation discipline.

### Rollout

Opt in per ticker with `selfCritique.enabled: true`. A cheaper `critiqueModel` paired with a premium structured pass is a sensible default.

## Require-citation pruning

The final transform in the pipeline guarantees that every bullet and quick hit a subscriber sees is backed by exactly one distinct, linkable article. It enforces three rules:

1. **Drop uncited rows** — a bullet or quick-hit whose `articleIndex` is null, out of range, or resolves to an empty URL is removed.
2. **One article per row** — within the dedup scope, only the first row for a given resolved article URL is kept; later rows citing the same article are dropped.
3. **Remove empty sections** — a section that reaches zero cited rows is set to `undefined` and omitted from the wire. A section with at least one cited row survives.

The pass runs **last**, after URL attachment, so `url !== undefined` is the only check needed.

### What is pruned

| Section                        | Prunable? | Notes                                        |
| ------------------------------ | --------- | -------------------------------------------- |
| `industry-pulse`               | Never     | Framing prose with no single source.         |
| `competitive-landscape`        | Yes       | Bullets variant.                             |
| `deals-and-movements`          | Yes       | Bullets variant.                             |
| `regulatory-policy-watch`      | Yes       | Bullets variant.                             |
| `disruptors-or-tech` (bullets) | Yes       | Only the bullets variant.                    |
| `disruptors-or-tech` (prose)   | Never     | Framing prose; exempt like `industry-pulse`. |
| `quick-hits`                   | Yes       | Items (same URL check).                      |

### Interaction with citation grounding

Citation grounding (`quality.citationGrounding`) runs earlier and can **unlink** a bullet (strip its article URL but keep the text) or **drop** it (remove the row). When both passes are on:

- `policy: drop` — grounding removes the row; the prune pass does not see it. Same outcome, single step.
- `policy: unlink` — grounding strips the URL; the prune pass then removes the row (no URL). Two steps, same result.
- `policy: warn` — grounding logs only; the prune pass performs the actual removal.

Pairing `policy: drop` with `requireCitation.enabled: true` keeps all removal logic in grounding. Pairing `policy: unlink` with pruning enabled gives the same reader-facing output through two passes. When both are enabled a log note is emitted at info level.

### Before / after example

**Before pruning** (resolved structure):

```
competitive-landscape: [{ text: "Rival bid", url: "https://a.com" }, { text: "No source" }]
regulatory-policy-watch: [{ text: "Permit delay" }]          ← no url
quick-hits: [{ text: "Hit 1", url: "https://b.com" }, { text: "Hit 2", url: "https://a.com" }, ...]
```

**After pruning** (dedupeScope: 'section'):

```
competitive-landscape: [{ text: "Rival bid", url: "https://a.com" }]   ← "No source" dropped
regulatory-policy-watch: undefined                                       ← section removed
quick-hits: [{ text: "Hit 1", url: "https://b.com" }, { text: "Hit 2", url: "https://a.com" }, ...]
```

Note: with `dedupeScope: 'newsletter'`, `Hit 2` would also be dropped because `https://a.com` was already seen in `competitive-landscape`.

### Config

| Field                                         | Default   | Description                                                                |
| --------------------------------------------- | --------- | -------------------------------------------------------------------------- |
| `requireCitation.enabled`                     | `true`    | Enable the pruning pass. Set to `false` for byte-for-byte current output.  |
| `requireCitation.sections`                    | all five  | Which body sections to prune. `industry-pulse` is always exempt.           |
| `requireCitation.dedupeArticlesWithinSection` | `true`    | When false, dedup is skipped (uncited rows are still removed).             |
| `requireCitation.dedupeScope`                 | `section` | `section` = per-section dedup; `newsletter` = one URL across all sections. |

### Observability

One info log per run: `{ sectionsRemoved, bulletsRemovedUncited, bulletsRemovedDuplicate, sectionsKept }`. Run details include a `requireCitation` block with the same four counters. A consistently high `sectionsRemoved` count for a ticker signals thin days — check the `lowInformationDay` signal from cross-run dedup and the yield snapshot for root cause.

### Rollout

The pass is **on by default**. To opt out a ticker while assessing output quality, set `requireCitation.enabled: false` in its Hermes config. The `dedupeScope: 'newsletter'` option is available but not the shipped default — use it when per-section dedup still allows duplicate articles across the briefing.

## KG competitor resolution

`GET /api/v1/content-generation` resolves the ticker's KG issuer anchor and returns two additional fields alongside `dataSources`:

| Field           | Type                                   | Description                                                                                            |
| --------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `competitors`   | `{ name: string; relation: string }[]` | Peer COMPANY entities off the issuer's `COMPETITOR` / `SECTOR_PEER` edges, ranked by weight.           |
| `issuerAliases` | `string[]`                             | All known names for the issuer (ticker symbol, legal name, KG aliases). Always at least symbol + name. |

### How competitors are resolved

1. The service looks up the ticker's KG anchor: the COMPANY entity linked to the ticker via `ticker_entity` with `source = SEED` (written by `ensureTickerIssuerCompanyAnchor` in the analysis agent).
2. From the anchor, it reads `entity_relation` rows where the issuer is either endpoint and the relation type is `COMPETITOR` or `SECTOR_PEER`.
3. The other endpoint entity is kept only if its type is COMPANY and its entity id or normalized names do not match any issuer alias (self-loop guard).
4. Duplicate peer entities (same entity id appearing in multiple edges) are deduped; the first occurrence wins.
5. Results are ordered by `weight` desc then `lastSeenAt` desc, capped at 8.

### Ranking and relation tags

`COMPETITOR` edges are the strong signal (explicit competitor data). `SECTOR_PEER` edges are the fallback when explicit edges are sparse. The `relation` field is passed through so consuming code (see [[72-competitor-anchored-competitive-landscape]]) can weight direct competitors differently from sector peers.

### Graceful degradation

A ticker with no KG anchor (not yet analyzed, or analysis found no issuer entity) returns `competitors: []` and `issuerAliases: [symbol, name]` without error. A ticker with an anchor but no peer edges returns `competitors: []`. Both cases are safe for consumers that have not yet been updated to use these fields, since both default to `[]` in the contract schema.

### Observability

No extra log line for the empty-graph path; the resolution is a few indexed reads well within the existing request latency budget. If you see unexpectedly empty `competitors` arrays for tickers that should have peer data, confirm the analysis agent has run `ensureTickerIssuerCompanyAnchor` for the ticker and seeded `COMPETITOR`/`SECTOR_PEER` relation types via `seed-kg-vocabulary`.

## Competitor-anchored Competitive Landscape

Builds on KG competitor resolution (above) to make the Competitive Landscape section actually competitive: bullets about the chosen company's rivals rather than the company itself.

### Where competitors come from

The `competitors` and `issuerAliases` fields returned by `GET /api/v1/content-generation` (see KG competitor resolution above) are threaded through `run.ts` into `generateNewsletterWithLlm`. No extra API call or database read is made at generation time.

### Prompt reframing

When the competitor list is non-empty, a directive block is injected into the user prompt directly above the article summaries:

```
Competitive Landscape must focus on these competitors of {issuer}: {Name1}, {Name2}, ....
Frame each bullet around a competitor's move, market share shift, product launch, or competitive threat.
Do NOT make these bullets about {issuer} itself.
```

Up to `quality.competitiveFocus.maxCompetitorsInPrompt` (default 6) named competitors are included. The system prompt's `competitiveLandscape` line is also updated to reinforce the competitor-centric framing.

When no competitors are available the prompt uses generic wording ("about {ticker}'s COMPETITORS") and no broken placeholder appears.

### Self-exclusion gate (`enforceCompetitiveFocus`)

After the polish pass, a deterministic gate walks each `competitiveLandscape` bullet and classifies it:

| Classification          | Condition                                        | Action under `drop` policy          |
| ----------------------- | ------------------------------------------------ | ----------------------------------- |
| **Competitor-grounded** | mentions a competitor (or both issuer and rival) | kept                                |
| **Generic**             | mentions neither issuer nor competitor           | kept                                |
| **Issuer-only**         | mentions issuer and no competitor                | dropped / flagged / logged (policy) |

`mentionsAny` does case-insensitive, word-boundary substring matching across all competitor names and aliases, and all issuer aliases.

**Policy options** (`quality.competitiveFocus.policy`):

- `drop` — remove the issuer-only bullet (product default)
- `flag` — prepend `[ISSUER-ONLY]` for operator review; bullet is kept
- `warn` — log only, structure unchanged

### Empty-KG fallback

When `competitors` is empty the gate is a complete no-op: all bullets are kept, `summary.evaluated === 0`. The section is never stripped just because a ticker's graph is sparse. As the analysis agent enriches the graph over time, the named-competitor path activates automatically.

### Floor and prune handoff

The gate defers empty-section cleanup to the require-citation pruning pass (plan 70):

- `requireCitation.enabled: true` — the gate may drop all bullets, leaving the section empty. The prune pass removes the now-empty section.
- `requireCitation.enabled: false` — the gate preserves at least the schema minimum (2 bullets) by downgrading the last excess drops to `flag`. This prevents the Competitive Landscape from silently disappearing when pruning is off.

### Observability

The gate emits one `info` log line per run when it fires, with `{ competitorCount, evaluated, dropped, flagged, policy }`. The `details` block on the success path includes:

```json
{
  "competitiveFocus": {
    "dropped": 1,
    "flagged": 0,
    "competitorCount": 5
  }
}
```

To soft-launch, ship with `policy: 'flag'` and monitor the `flagged` rate in run-details for a week before switching to `drop`.
