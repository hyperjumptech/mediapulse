## Purpose

`@mediapulse/knowledge-graph` reads the MediaPulse knowledge graph in Organon over SPARQL and sends it articles to ingest. agent-data-api uses its client to load ticker profiles. domain-api uses it to keep the `ticker` table in step with the listed companies the graph holds.

## Exports

- **`createOrganonSparqlClient({ baseUrl, apiKey, timeoutMs, fetchImpl?, includeInferred?, includeProvenance? })`** returns a function that posts a SPARQL `SELECT` to `POST /api/v1/sparql` and resolves to its bindings. It asks for inferred answers (`?inferred=true`) unless `includeInferred` is false, and adds the history graph (`?provenance=true`) when `includeProvenance` is true. It refuses a query longer than Organon's limit and reports the status and the start of the body when Organon fails.
- **`buildIngestionRequest(article)`** turns one placed article into the request Organon's `POST /api/v1/ingestion` takes, as the developer page "How to ingest an article" describes. The content opens with a header the model reads: the title, every ticker the article is placed for, its publish date and its publisher. The snippet and body follow, and only the body is cut to stay within 200,000 characters. The metadata facts become the article's Data source: canonical URL, URL, title, description, publish date, `mp:SourceNews` and the publisher's IRI. A fact Mediapulse has no value for is left out.
- **`createOrganonIngestionClient({ baseUrl, apiKey, timeoutMs, fetchImpl? })`** returns the calls the ingestion agent makes with its write key: `findPublisherIri` and `createPublisher` by registrable domain, `startIngestion`, `listFailedJobs` (100 per page, with the canonical URL each job was for) and `retryJob`, which answers `not-retryable` when Organon refuses with 404 or 409. For the evidence check it adds `getJobStatus`, which answers `null` for a job the key never started or Organon has deleted, and `articleEvidence(canonicalUrl)`, which returns the article's annotations with their tickers and quotes, and the figures it added that no annotation names. The figures come from the article's versions in the history graph, so that query runs with `includeProvenance` and without inferred answers. A domain that isn't a plain registrable domain is never put in a query.
- **`loadListedCompanies(runSparql)`** runs `LISTED_COMPANIES_QUERY` and returns one `{ symbol, name }` per `mp:ListedCompany`, sorted by symbol. The symbol is trimmed and uppercased. The name is the legal name, or the label when the company has none. Rows without a symbol or a name are skipped, and it throws when nothing usable comes back.
- **`syncTickersFromKnowledgeGraph(companies, db)`** adds the symbols the table lacks and removes the tickers the graph no longer lists. It never renames a ticker, so an existing name stays as it is. A ticker is only removed when nothing references it: no subscribers, newsletters, search queries, delivery, content generation or query analysis runs. Unlisted tickers that are still referenced are kept and returned as `keptUnlisted`. When more than `MAX_TICKER_REMOVALS_PER_SYNC` (25) tickers would be removed, it throws `TickerRemovalLimitError` and changes nothing, which guards against a partial answer from the graph. It returns `{ added, alreadyPresent, removed, keptUnlisted }`, where the last field lists, sorted, the symbols in the table that the graph does not list.

## Consumers

- **agent-data-api** builds its ticker profile source on the SPARQL client.
- **domain-api** runs the **Sync from knowledge graph** action on the tickers page. See [Domain API](/mediapulse/apps/domain-api).
