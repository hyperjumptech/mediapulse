Use this page as a **production reference**: required and optional environment variables per app, how to obtain values, and a sensible deploy order. Variable definitions live in **`packages/hermes/env`** and **`packages/mediapulse/env`** (see [env](/hermes/packages/env)). Sensitive values must **not** use the `NEXT_PUBLIC_` prefix.

**Domains:** Hermes holds **orchestration** data; Mediapulse holds **domain** data. You can use one PostgreSQL instance with separate schemas or separate databases—see [Hermes and Mediapulse domains](/architecture/domains).

All **install** and **build** commands below run from the **repository root** unless noted. You need **Node 20+**, **pnpm** (see root `package.json` `packageManager`), and **Bun** for services that run the compiled `dist/server.js` bundle.

---

## Prerequisites

Provision **three** PostgreSQL logical databases (they can be three schemas on one server):

| Database role              | Used for                                       | Connection env var(s)                                                                      | Deploy migrations                                                            |
| -------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| **Hermes (orchestration)** | Pipelines, schedules, API keys, agent registry | `ORCHESTRATION_DATABASE_URL` (and optional legacy `DATABASE_URL`)                          | `pnpm --filter @hermes/orchestration-database db:migrate:deploy`             |
| **Mediapulse (domain)**    | Tickers, newsletters, KG, subscribers, etc.    | `MEDIAPULSE_DATABASE_URL`                                                                  | `pnpm --filter @mediapulse/database db:migrate:deploy`                       |
| **DataQueue**              | hermes-worker job queue (scheduler)            | `PG_DATAQUEUE_DATABASE` (same host is fine; use `?schema=dataqueue&search_path=dataqueue`) | `pnpm --filter @hermes/worker run migrate-dataqueue` (with queue URL in env) |

## Hermes

Deploy in this order: **agent-auth-api → agent-registry-api → dashboard → (scheduler API key) → hermes-worker**.

### 1. agent-auth-api

**Package:** `@hermes/agent-auth-api` · **Path:** `apps/hermes/agent-auth-api`

| Step                 | Command                                                                                                                                                        |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Install dependencies | `pnpm install --frozen-lockfile`                                                                                                                               |
| Build                | `pnpm --filter @hermes/agent-auth-api build`                                                                                                                   |
| Run (production)     | From app directory: `PORT=8080 bun run ./dist/server.js` (set env vars in the process environment or `.env`). Docker: `apps/hermes/agent-auth-api/Dockerfile`. |

| Variable                     | Example value                         | Explanation                                                           |
| ---------------------------- | ------------------------------------- | --------------------------------------------------------------------- |
| `ORCHESTRATION_DATABASE_URL` | `postgresql://…?schema=orchestration` | Orchestration database URL after migrations.                          |
| `AGENT_AUTH_JWT_SECRET`      | _(random 32+ chars)_                  | Signs and verifies JWTs for `POST /api/token` and `POST /api/verify`. |
| `TEMP_ADMIN_USERNAME`        | _(strong username)_                   | Basic-auth admin for API key management on this service.              |
| `TEMP_ADMIN_PASSWORD`        | _(strong password)_                   | Must match other Hermes services using the same admin pair.           |
| `PORT`                       | `8080`                                | HTTP port (default in code).                                          |

| `TEMP_ADMIN_PASSWORD`           | _(same as auth API)_                  | Same as auth API.                                                                                                           |

### 4. hermes-worker

**Package:** `@hermes/worker` · **Path:** `apps/hermes/worker`

| Step                 | Command                                                                                                 |

| Build                | `pnpm exec turbo build --filter=@hermes/worker`                                                         |
| Run (production)     | From app directory: `bun run ./dist/server.js` (see `package.json` `start`: `bun run ./dist/server.js`) |

| Variable                        | Example value                                           | Explanation                                                                             |
| ------------------------------- | ------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `DATABASE_URL`                  | `postgresql://…`                                        | Required by worker env schema (often same cluster as orchestration; schema may differ). |
| `ORCHESTRATION_DATABASE_URL`    | `postgresql://…?schema=orchestration`                   | Orchestration Prisma when `@hermes/env` loads.                                          |
| `TEMP_ADMIN_USERNAME`           | _(same as dashboard)_                                   | Required with `@hermes/env`.                                                            |
| `TEMP_ADMIN_PASSWORD`           | _(same as dashboard)_                                   | Required with `@hermes/env`.                                                            |
| `PG_DATAQUEUE_DATABASE`         | `postgresql://…?schema=dataqueue&search_path=dataqueue` | DataQueue storage after `migrate-dataqueue`.                                            |
| `AGENT_AUTH_API_URL`            | `https://agent-auth-api.example.com`                    | Mint JWTs for scheduled agent invocations.                                              |
| `AGENT_API_KEY`                 | _(scheduler key)_                                       | Same scheduler API key as the dashboard.                                                |

| `MEDIAPULSE_API_URL`            | `https://domain-api.example.com`                        | If worker must call domain-api without a stored integration row.                        |
| `DOMAIN_INTEGRATION_AUTH_TOKEN` | _(shared secret)_                                       | Must match domain-api when using `MEDIAPULSE_API_URL`.                                  |
| `PROCESSOR_BATCH_SIZE`          | `10`                                                    | Optional DataQueue tuning.                                                              |
| `PROCESSOR_CONCURRENCY`         | `3`                                                     | Optional DataQueue tuning.                                                              |

### 3. Mediapulse agents

Examples: **`@mediapulse/data-collection`**, **`@mediapulse/content-generation`**, **`@mediapulse/delivery`**, **`@mediapulse/ticker-echo`** under `apps/mediapulse/agents/*`. Merge **`packages/mediapulse/env/env.example`** with the matching **`packages/mediapulse/env/env.agents.*.example`**.

| Step                 | Command                                                                                                                       |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Install dependencies | `pnpm install --frozen-lockfile`                                                                                              |
| Build                | `pnpm exec turbo build --filter=@mediapulse/data-collection` (swap package name per agent)                                    |
| Run (production)     | From the agent app directory: `bun run ./dist/server.js` (set `PORT` per agent; defaults e.g. `4001`, `4002`, `4003`, `4010`) |

| Variable             | Example value                        | Explanation                                                        |
| -------------------- | ------------------------------------ | ------------------------------------------------------------------ |
| `AGENT_AUTH_API_URL` | `https://agent-auth-api.example.com` | Verify invocation JWTs (recommended for all agents in production). |
| `AGENT_DATA_API_URL` | `https://agent-data-api.example.com` | Required for agents that call the data API (not ticker-echo).      |
| `PORT`               | `4001` (per agent)                   | Agent HTTP port.                                                   |

**Agent-specific** (see each agent’s `env.agents.*.example` and README): e.g. **`JINA_API_KEY`**, **`SERPER_API_KEY`** (data-collection); **`RESEND_SENDER`**, **`RESEND_API_KEY`** (delivery); OpenAI is configured on **Agent configs** in Hermes for content-generation, not env.

**Auto-register** (optional): set **`AGENT_REGISTRY_URL`**, **`AGENT_PUBLIC_URL`**, **`AGENT_AUTH_API_URL`**, **`AGENT_API_KEY`** (scheduler key) so the agent can call `POST /api/agents/register` on agent-registry-api.

**Knowledge-graph agents** (**query-analysis**, **analysis**): same install/build/run pattern; see [Knowledge Graph](/architecture/knowledge-graph/knowledge-graph) and each agent’s README for extra env (LLM keys, etc.).

## Secure agent communications

- **JWT-only invocation:** Agent invocation uses **only** short-lived JWTs. Hermes and hermes-worker call `POST /api/token` with a **scheduler API key** (created by an admin in the Hermes dashboard, API keys, purpose `scheduler`) to obtain a JWT, then send `Authorization: Bearer <jwt>` to agents. Agents forward that same header to **agent-data-api** on each run. Agents, agent-data-api, and agent-registry-api verify the JWT via `POST /api/verify`. Raw API keys are never sent to agents for invocation or data API calls. For **startup registry registration**, agents mint a JWT with the same scheduler key via `POST /api/token`. Set `AGENT_AUTH_JWT_SECRET` on agent-auth-api (required).
- **HTTPS:** Use HTTPS for all service URLs in production. Set `REQUIRE_HTTPS_AGENT_ENDPOINTS=true` so hermes-worker rejects non-HTTPS agent endpoints (except localhost).
- **No bypass in prod:** Do not set `ALLOW_ANY_BEARER_FOR_LOCAL=true` (or equivalent) in production; keep it for local dev only.

## Summary

- **Order:** Prerequisites (three DB roles + migrations) → **Hermes** (auth API → registry API → dashboard + scheduler key → worker) → **Mediapulse** (agent-data-api → domain-api → agents).
- **Secrets:** Never commit real values; use your platform’s secret storage. Scheduler **`AGENT_API_KEY`** is created once in the Hermes dashboard (purpose `scheduler`).
- **JWTs:** Hermes and worker mint tokens with that key via agent-auth-api; agents and data API verify with **`AGENT_AUTH_API_URL`** / **`AGENT_AUTH_JWT_SECRET`** on the auth API.
